# Codex 客户端方案

维护责任：客户端研发；最后核查：2026-11-03。状态：0.1.2 已通过官方 CLI 更新本地安装并启用，缓存资产与最终审核包一致；性能、目录热区与键盘焦点完成记录范围内的验证。真实 Codex 完整 GUI、深色与窄窗未覆盖，候选未公开发布。基线为 `3dd7e30` 加本轮工作区改动。字段以 [contract.ts](../../src/codex/contract.ts) 与 [validation.ts](../../src/codex/validation.ts) 为真源；产品与视觉依据见[产品规则](../产品/业务规则.md)及[工作区设计](../设计/Codex工作区.md)。

实现为一个 MCP App 审阅工作区，加宿主管理的本地 stdio。仓库选择、真实 Git 树、完整／增量 Diff、CR、已审、意见和人工复核均在同一工作区内。没有 HTTP 监听、后台服务、额外登录或上传。CodeMirror 两侧只读，`editCode: false`；源码保存未通过 E1，不把候选方式当已交付功能。

## 二、仓库、CR 与页面如何绑定

open 工具只提供空工作区资源。bootstrap 返回进程 epoch、随机 capability 和独立 view ID；每个请求校验二者，凭据不落盘。顶部持续提供项目切换，最近项目一键打开，“选择文件夹…”调用包内自有 AppKit 组件，手动绝对路径折叠备用。子目录经现有 openWorkspace 的 Git／realpath 校验解析根。当前 `roots: false`，不依赖未知宿主候选；`folderPicker` 单独表示当前平台及组件可执行性。最近记录不等于权限，每次重查；不 checkout、不递归扫描用户目录、不将插件 cwd 当仓库。打开目标失败保留旧输入，显示失败目标并提供重新选择。

候选新目录的明确 rejected 只显示在选择弹窗，不把仍可读的当前仓库置为失效，也不清除当前原有的错误。切换前旧 CR 草稿保存失败仍阻止切换并保留全局保存错误；重新打开当前根、初始化、要求重连的认证错误及 partial／unknown／通信失联继续启用全局保护。弹窗从本次抛出的失败读取文案，不能借用旧仓库的错误冒充候选目录错误。原项目在途 Diff 在候选被拒绝后继续完成或报告其原有错误；只有成功采用新项目时才使旧读取失效并重置旧加载状态。选择成功后的 Diff 加载失败则属于新的当前项目，照常显示其失败状态。

文件夹选择只在明确点击后启动，使用系统单选目录窗口。初始位置来自当前已绑定仓库或最近记录；失效初始位置由系统面板处理；页面不能传入可执行文件或命令。start／poll／cancel 是短请求，选择结果留在进程内，不进入业务 operation 回执；同一选择 ID 重试不会再开窗口，其他 view 不能读取或取消该选择。组件每个用户临时目录用系统 advisory lock 防止多个 stdio 同时弹窗；不创建常驻进程。

UI 每 500 毫秒串行查询；取消或关闭弹窗不改变仓库、最近记录或草稿，页面关闭后取消并丢弃晚到结果。连接中断可显式继续查询原选择或取消，不把选择中断变成审阅保存 unknown。运行时 120 秒总超时、15 秒无查询租约，关闭 stdio 时终止并等待组件退出；组件另有超时和父进程退出检测。成功仅返回目录，随后原有打开流程先保留旧草稿再校验 Git；非仓库不创建或初始化 Git。组件缺失／启动失败时说明原因并保留手动入口。

首次启用合并在新建审阅确认内，说明 `.reviewslate/codex/` 与追加规则 `/.reviewslate/codex/`。只有 initialize 才创建应用目录，读取不初始化。初始化跨多个文件，失败保留原 operation ID 核对和接续，不假装完全未写入。

上下文绑定仓库 ID、epoch、CR、检出分支、完整基点和投影 revision。内容动作再核对指纹，评论修改再核对 ID／revision／状态／删除状态。写入锁内重读；活动 CR 是每仓库／分支一份持久化事实，另一页面切 CR 后旧请求失效。进程按仓库持有 ReviewService，页面 generation 隔离旧异步读取。

外部切分支或其他页面切活动 CR 时，普通 flush 和业务动作仍拒绝旧上下文。错误条提供显式“保留原 CR 草稿并打开当前分支”：saveView 的 retainInactive 仅保存原 CR 的导航／草稿，锁内检查该 CR 仍存在、未归档／永久删除且原分支、基点吻合，不改活动 CR、不提交意见或已审。持久确认后才应用当前分支的视图。保留失败不跳转、不报已保存；原 CR 不可写时可打开“导出当前草稿”只读文本，复制完整输入和归属到用户选择的位置，导出展示本身不代表已保存。

归档读取不改变活动指针，只展示资料、意见／回执及已有已审快照，不承诺还原归档时所有未审工作区文件。恢复并核验分支后才显示当前磁盘完整 Diff。

## 三、内部工具契约

字段、动作和工具映射直接引用源码，不维护第二份 schema。只有 `reviewslate_open` 模型可见，其他工具均 app-only。路径、代码、意见、草稿及凭据在 `_meta.reviewslate`；content 仅固定摘要，不使用 structuredContent 携带资料。真实 Codex 是否保持该边界仍属 H1，不能由 stdio 声明推导宿主保密性。

读取动作 refresh／bases／diff／inspectReview／operation 不初始化、不重写派生清单、不改变 CR。树传摘要，内容按文件读取。没有源码保存、任意命令、fetch、checkout、HTTP 或自动发送会话入口。

完整 Diff 直接核对当前仓库、epoch、分支、活动 CR 和基点，读取目标文件的真实字节及最新意见，再次核对归属后返回；不扫描其他工作区文件。增量 Diff 另读取已审记录及所选侧的快照；归档 Diff 末尾重查归档状态和永久删除标识。单文件读取不更新整仓 revision；当目标指纹与树中记录不符时，页面先显示新 Diff、保留输入并禁写，再异步触发最多一轮整仓刷新。刷新期间再次变化则保留提示，等待显式刷新；不能以新文件内容冒充其他文件也已核查。迟到 Diff 不得回滚已采用的新 context。

导航和草稿保存只依赖 CR 归属、视图 CAS revision 与完整输入，不扫描源码。它保留写前身份检查、原 operation／view 归属、持久化意图及回执；内容变化本身不阻止保存草稿，跨分支、跨 CR 和归档仍拒绝普通保存。显式 retainInactive 的原 CR 检查不变。业务动作继续完整刷新和核对展示指纹、目录成员；同一动作已完成服务刷新时直接投影该结果，避免返回前再扫一次。

写结果分 committed／rejected／partial／unknown；稳定错误码附 retry 和可选 committedParts。JSON-RPC ID 仅关联当前连接，operation ID 负责持久化核对；不同参数复用 ID 拒绝。新增意见另用 request ID 防重复；编辑额外核对状态，因为解决动作不改变正文 revision。失效编辑不能退化为新增。文件评论没有选区也必须带当前内容指纹。

增量 Diff 的渲染身份包含实际左右快照 hash、侧别与空态 reason，不只看工作区 fingerprint；标记已审改变左侧快照后立即重建视图和“无变化”提示。基点选择器从已保存 defaultBase.kind/ref 初始化，指定提交方式回填完整 SHA；设置默认值不改变当前 CR。

## 四、状态归属与连续性

| 状态 | 实际归属 |
| --- | --- |
| Git 字节、分支、模式 | 真实仓库，读取和业务写入前重查；工具不写源码 |
| CR、基点、已审、意见／回执 | 独立数据根中的既有引擎格式 |
| 导航、新评论和编辑草稿 | 每 CR／view 一个 view.json，完整内容、单调 sequence、CAS revision |
| 页面输入、IME 中间态、在途请求 | 当前页面；切对象／CR／仓库先 flush，失败保留 |
| 语言、最近仓库、最后仓库 ID | 应用注册表，跨仓库保持 |
| capability、Git 缓存 | 进程内，退出失效 |
| 文件夹选择结果、取消标记 | 进程内按 view／选择 ID 隔离，短期缓存，不持久化、不授予仓库访问 |

草稿保存对象、正文及完整侧选区；编辑另有原评论 ID／revision／state 和编辑前新草稿引用。最多 200 份，每份正文 20,000 字符。旧序号、冲突或失败回执不清除后来输入。归档草稿只读，归档导航仅页面内；永久删除清理该 CR 的 views 和 handoffs。

每次挂载产生新 view ID，恢复当前仓库／分支／CR 最新已保存副本并写新槽，旧槽保留。当前 UI 没有多历史副本选择或合并页面。导航保存目标、展开、完整／增量模式、侧别、锚点与滚动；内容未变精确恢复，变化只按可确认锚点定位。没有持久化确认的最后输入不保证关闭后恢复，页面明确显示待保存／失败。

树以文件和评论列表引用缓存线性汇总结果，内容等值的最新响应保留列表引用，但采用最新上下文。选中文件、保存状态和 Diff 加载状态变化保留树节点、焦点及滚动；目录成员只在需要操作时读取，避免逐节点反复遍历全列表。

目录展开箭头与已审 checkbox 的 label 分别占 32 × 32 px，间距 2 px，行高至少 34 px，14 px 箭头居中；叶节点保留同宽展开空位。箭头只展开／收起，目录名打开概览与意见，label 由原生 checkbox 激活；热区不覆盖相邻控件。浅／深主题沿用项目紫蓝变量，高对比使用系统 Highlight。展开后恢复箭头焦点；由键盘发起已审操作后，在用户未移走焦点、未改变对象等条件下恢复原 checkbox 焦点，用户主动 Tab 离开时不抢回。Space 保存后再次按 Space 可撤回，已在最终包的自有 WKWebView 应用复验；深色与窄窗尚未实测。

自动刷新合并在途请求，完成后按本轮耗时的两倍延后，最短 5 秒、最长 60 秒；仍真实扫描并重读当前 Diff，不以停止检查换取速度。刷新有独立状态，不阻止切文件或先保存草稿；相同页面代次、仓库、CR、revision、路径、模式及侧别的在途 Diff 合并。页面隐藏、输入组合、弹窗、未保存输入、未知操作或陈旧状态时不启动周期扫描；离开页面清理定时器。

语言为 auto／zh-CN／en。auto 下 zh 或 zh-* 使用简中，其余／缺失使用 English。偏好保存成功才切语言，失败保持原选择；不翻译意见、回复、代码、路径、分支、commit，不提交业务资料。可见页刷新不建立后台 watcher。普通 UTF-8 完整内容不以少量 hunk 替代；真实宿主消息体及大文件体验仍须实测。

## 五、独立进程、幂等与失效恢复

仓库 `.reviewslate/codex/write.lock` 串行化持久化写入与需要事务一致性的读取，再进入内部 engine／CR／notes 锁。完整刷新仍在进程队列中独占 `ReviewService.view`，但 Codex 使用 `publishOnRefresh: false` 只读路径，因此整仓扫描不持有仓库写锁。Diff 完全不访问可变的服务视图，草稿保存继续持有仓库写锁覆盖校验、CAS 和回执；二者可在后台扫描期间完成。其他业务写入仍走队列及写锁，不能通过并行分支绕过归属检查。

只读刷新读取的 Git 与外部元数据不是整个仓库的事务快照；服务末尾重核活动 CR／分支，后续业务写入重新计算 revision。进程内队列不代替跨进程锁。EOF／退出先拒绝新请求，等待队列、独立 Diff 读取及在途草稿持久化，再关 stdio；没有守护进程。

写请求先保存应用级操作路由，包括参数摘要、原 view、仓库、CR，不复制正文。仓库动作再写 pending receipt、规范数据和 committed receipt。偏好／最近仓库的提交标识与 registry 同文件原子保存；saveView 有仓库 receipt 并保留原 view 归属。

重连先 bootstrap，再无 workspace ID 查询原 operation。查询重查路径、绑定新 capability；committed 按原动作类型返回，view 返回原槽当前副本，偏好返回当前保存值。旧偏好重试不回滚后来的语言。rejected 为明确拒绝；not-found 为无已记录意图，可明确发起新请求；pending 需核对，不能自动重放或换新 ID。

显式接续 pending 复用原 ID／参数；新 capability／epoch 不改变业务摘要，saveView 仍写原槽。not-found 的保存可明确成为新 view／新 operation。业务 pending 只按已审引用、评论 request ID／目标摘要、view 内容或 tombstone 核对；不可判定保持 unknown。落盘后回执失败为 partial／unknown，不能报未写入，迟到回执不能清新输入。

pending 索引的原 view／仓库／CR 路由不可由重连请求覆盖，更新只改变状态及失败信息。回执读取和每次回执写入都从仓库根逐级验证 operations 父目录，不跟随被替换的符号链接；旧 intent 核对失败不能把原结果未知改写成“原写入已拒绝”。

查询 pending 会暂时保持旧页面上下文。用户确认重试成功后，页面必须重新打开同一仓库并核对原 CR、分支、完整基点和当前有效 context，再用新进程 epoch 保存后来输入；不能只更新重放请求的 epoch。若归属变化，原操作的成功仍已确认，但后来输入不自动迁移或提交，显示失效状态并保留显式保留／导出入口。

残留锁不按超时删除。先停止相关进程／Agent，再检查 marker、主文件／备份、日志和删除标识；没有退出证据保持错误。操作索引缺失不能复活永久删除 CR，业务 tombstone 持续拒绝旧请求。布局与恢复见[数据协议](数据协议.md#codex-独立存储方案)。

## 六、直接编辑的候选实现与门槛

当前两侧只读，E1 未实施，没有代码缓冲恢复副本或保存按钮。现有数据写入器以 0600 临时文件替换目标，不保留源码模式；普通 lstat → rename 不能与外部编辑器构成原子 compare-and-swap，可能丢失竞争版本。此前合成实验确认模式改变，不能直接移用该数据函数。

后续候选须分别验证 UTF-8／BOM／换行／权限、链接与目录身份、硬链接／ACL／扩展属性、外部竞争、强杀和丢回执。先保存原版本和候选字节，再用能保留竞争版本的受控替换；不默认覆盖或自动回滚。源码保存和审阅刷新分开报告。通过前维持只读，由产品确认 AC-06 适用范围，不阻止当前审阅闭环验收。
