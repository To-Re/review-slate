# 项目文档

维护责任：项目维护者；最后核查：2026-11-03。当前行为基线为 `d7e6b0d`（1.0.1）。

ReviewSlate 当前公开版本为 **1.0.1**，提供 VS Code 系编辑器扩展和本地文件交接。后续开发优先推进 Codex 内的连续审阅，各应用独立保存进度，DeepSeek Harness 延后。Codex 专用插件与原生审阅界面均未实现；跨宿主数据互通、同步和迁移不在首版范围内。

## 按任务阅读

| 要完成的事 | 入口与内容 | 维护责任 |
| --- | --- | --- |

| 读写评论、回执或恢复数据 | [数据协议](data.md)：字段真源、归属、版本、持久化与备份 | 研发负责人 |

涉及多个领域时，先确定产品规则，再核对架构和数据协议，最后使用贡献指南中的验收入口。字段级约定以数据协议链接的代码定义为准；文档不另存一份可写的 schema。

## 当前能力与边界

| 能力 | 当前行为 | 详细规则 |
| --- | --- | --- |
| 持续审阅 | 固定基点，对比已保存工作区；按分支与基点隔离 CR，内容变化后提醒复审 | [产品规则](product.md)、[使用指南](usage.md) |
| 评论与人工复核 | 文件、目录和选区评论；Agent 回执匹配评论版本后显示待复核，由人解决 | [使用指南](usage.md)、[数据协议](data.md) |
| 本地文件交接 | 用户复制指定 CR 的清单入口，Agent 读取 JSON 并写独立回执；扩展不调用 Agent | [交接操作](usage.md#交给-agent)、[数据协议](data.md) |
| 数据恢复 | 扩展存储保存 CR、已审记录和快照，`.code-review/` 保存评论与回执；完整备份需要两处数据 | [数据协议](data.md) |
| 多宿主使用 | VSIX 面向 VS Code、Trae、Trae CN；扩展存储各自独立，同一仓库的评论仍在 `.code-review/`。不提供自动同步、迁移或完整进度共享 | [安装条件](../README.md#安装)、[架构](architecture.md) |

## 发布与验证边界

发布内容见 [1.0.1 Release](https://github.com/To-Re/review-slate/releases/tag/v1.0.1) 与[更新记录](../CHANGELOG.md)。以下证据仅适用于该发布基线。

1.0.1 的实机验证覆盖 macOS / Trae CN 3.4.11（内核 1.107.1）的 VSIX 安装、窗口重载、审阅设置、新建入口、SHA 输入与 Git 图形菜单显示。该记录不等于完整流程的实机验收；VS Code、Trae 和 Remote SSH 尚未完成本版本实机验证。

1.0.1 的 112 项自动化测试和 Ubuntu / macOS 测试、打包已通过，记录见[对应 CI 运行](https://github.com/To-Re/review-slate/actions/runs/41455891420)。自动化使用真实 Git、临时合成仓库和模拟编辑器 API，覆盖范围见[验收矩阵](../CONTRIBUTING.md#验收矩阵)。构建通过、自动化通过、真实宿主验证和公开发布分别记录，不能互相替代，也不证明 Codex 目标已实现。

## 文档如何维护

本文负责文档导航、当前能力与验证边界；产品、架构、数据和 Codex 设计分别维护领域规则，路线图只维护未来工作。行为变化时，同次更新对应规则、用户操作、验收条件及受影响的本页摘要；发布时更新版本、证据和[更新记录](../CHANGELOG.md)。保留 `data.md` 作为数据说明的稳定入口。

当前正文写已确认的事实与决定，历史变化通过 Git、Issue / PR 和 Release 追溯。待办在路线图中说明下一步及完成条件，不另建重复模板或按角色保存项目总状态。安全报告和数据披露要求见 [SECURITY.md](../SECURITY.md)。
