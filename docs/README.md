# ReviewSlate 文档

负责人：主负责人；状态：现行；最后核查：2026-11-04。本文适用于 `main` 的 VS Code 系 VSIX 扩展，依据本分支实现与各角色的独立核查维护。

用户从[使用指南](用户文档/使用指南.md)开始；维护者先读[项目现状](项目现状.md)和[在途状态](项目状态.md)。参与开发前阅读 [CONTRIBUTING.md](../CONTRIBUTING.md)、[AGENTS.md](../AGENTS.md)和[协作规范](协作规范.md)。

`main` 只维护 VSIX，兼容目标包括 VS Code、Trae 和 Trae CN。Codex 的开发源码与文档在 [beta 分支](https://github.com/To-Re/review-slate/tree/beta)，不属于本分支的交付范围。

本分支版本为 1.0.3，新增变更树筛选；安装入口见 [1.0.3 Release](https://github.com/To-Re/review-slate/releases/tag/v1.0.3)，验证范围与后续工作见[项目状态](项目状态.md)。

## 按角色查阅

每个专业方向一个目录，由该角色直接维护正文。主负责人维护总入口、现状、在途状态和协作规范，协调跨目录变更。

| 责任角色 | 权威入口 | 回答的问题 |
| --- | --- | --- |
| 产品 `product_manager` | [产品](产品/README.md)、[业务规则](产品/业务规则.md)、[验收条件](产品/验收条件.md) | 为谁解决什么问题，进度与评论如何判定，怎样算完成 |
| 设计 `designer` | [设计](设计/README.md) | 入口、文件树、Diff、评论与状态如何衔接 |
| 客户端 `frontend_engineer` | [客户端](客户端/README.md)、[本地审阅引擎](客户端/本地审阅引擎.md)、[数据协议](客户端/数据协议.md) | 模块职责、读取与调度、持久化和恢复边界 |
| 测试 `qa_engineer` | [测试](测试/README.md)、[验证记录](测试/验证记录.md) | 哪些场景需要验证，哪个版本实际测过，哪些仍未覆盖 |
| 代码审核 `code_reviewer` | [代码评审](代码评审/README.md) | 正确性、回归风险与关键测试缺口 |
| 安全审核 `security_reviewer` | [安全](安全/README.md) | 信任边界、数据保护、公开内容和产物审核 |
| 写作 `writer` | [使用指南](用户文档/使用指南.md)、[数据与故障处理](用户文档/数据与故障处理.md) | 如何安装、完成一轮审阅、备份和排查问题 |
| 编辑 `editor` | [文档评审](编辑/README.md) | 事实、论证、阅读顺序和文档间一致性 |

代码是字段级契约来源，文档说明规则与取舍，不维护第二份可写 schema。实际测试、安装和发布分别记录；代码存在或本地测试通过不代表所有编辑器已实测。

## 接续任务

1. 核对所在分支、工作区差异及[在途状态](项目状态.md)，保留其他贡献者的改动。
2. 读取本次涉及的角色正文与实现，确认写入边界和依赖。
3. 完成改动、相关验证和所属文档；跨目录问题交主负责人协调。
4. 按实际被检版本交接证据、遗留项和下一步，移除被替代的旧文档并修复引用。
