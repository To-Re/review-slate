# ReviewSlate 项目资料

负责人：主负责人；状态：现行；最后核查：2026-11-03。本文是项目协作入口，来源为仓库实现、各角色的领域核查及已发布版本证据。

先读[项目现状](项目现状.md)，了解当前能用什么；再读[项目状态](项目状态.md)，接续进行中的工作。用户安装与操作从[使用指南](用户文档/使用指南.md)进入，贡献方式见根目录 [CONTRIBUTING.md](../CONTRIBUTING.md)。

## 角色与权威入口

每个专业方向有独立目录，责任角色直接维护本领域正文。主负责人维护本目录的四份总入口，协调跨领域契约与最终交付。分工、验证和更新要求见[协作规范](协作规范.md)。

| 责任角色 | 目录入口 | 负责的事实与决定 |
| --- | --- | --- |
| 产品 `product_manager` | [产品](产品/README.md) | 用户目标、范围、业务规则、验收条件与产品取舍 |
| 设计 `designer` | [设计](设计/README.md) | 流程、信息架构、交互、视觉状态及设计验收 |
| 客户端 `frontend_engineer` | [客户端](客户端/README.md)、[本地审阅引擎](客户端/本地审阅引擎.md)、[数据协议](客户端/数据协议.md)、[Codex 接入](客户端/Codex接入.md) | 插件本地逻辑与数据、界面状态、宿主适配、构建安装与生命周期 |
| 测试 `qa_engineer` | [测试](测试/README.md)、[验证记录](测试/验证记录.md) | 场景、方法、证据、缺陷与覆盖缺口 |
| 代码审核 `code_reviewer` | [代码评审](代码评审/README.md) | 独立审查的范围、结论和复核边界 |
| 安全审核 `security_reviewer` | [安全](安全/README.md) | 信任与数据边界、披露检查和当前审核范围 |
| 写作 `writer` | [用户文档](用户文档/使用指南.md) | 对外使用说明；专业事实由所属方向确认 |
| 编辑 `editor` | [文档评审](编辑/README.md) | 独立检查事实支持、表达与阅读路径，记录结论与未覆盖范围 |

编辑角色向对应作者交回问题，在自己的目录记录评审结论，不复制领域正文。代码定义是字段级契约真源，CI、Release 与具体验证记录是执行结果来源，不能用文档存在替代验证。

## 接手一个任务

1. 核对 [AGENTS.md](../AGENTS.md)、工作区差异、项目现状和在途状态。
2. 读取本次涉及的角色目录及其指向的实现。需求是目标，代码与运行证据是现状，两者有差距时明确登记。
3. 完成所属领域的改动和验证，更新当前正文；共享文件或跨领域问题交主负责人协调。
4. 以被检版本、实际结果和遗留项交接。开发、验收、安装和公开发布分别确认。

当前公开源码和 VSIX 位于 [GitHub 仓库](https://github.com/To-Re/review-slate)与 [Releases](https://github.com/To-Re/review-slate/releases)。本地未入库的接入试验不属于已发布产品，范围见[项目现状](项目现状.md)。
