## 发现与修复复核

**P2：排队中的自动恢复全部仍使用旧导航与旧可见性判断。已关闭。**

在“未审核”下定位被隐藏的已审评论对象 A，等待偏好写入期间打开 B；旧请求结束后仍把筛选及持久偏好改为全部。另一触发顺序是手动切“有评论”尚在写入，定位 A 将自动恢复全部排在其后；手动模式已让 A 可见，旧自动任务仍将其覆盖。两者均在修复前独立复现，影响用户最新的导航上下文或手动筛选选择。

修复位于 [`setTreeFilter` 与 `visibleCommentTarget`](../../src/extension.ts)：自动请求在队列实际执行时重查导航、服务、CR 和当前可见目标；偏好写入返回后再查，已过期的写入在同一筛选队列中补偿原模式，再处理后续手动选择。仅实际切换模式时提示成功。最终候选上，两个原始复现均通过，选中对象、显示模式和持久值符合预期。永久回归见 [`tree-filter.test.cjs`](../../test/tree-filter.test.cjs)。审核者未修改实现。

## 数据流与提交边界

| 检查范围 | 代码核查结果 |
| --- | --- |
| 完整索引与可见索引 | 先构建完整树及目录统计，再投影匹配对象与祖先；旧目录节点的 `getChildren` 读取当前可见索引。目录自有评论不放出无评论后代，文件 / 目录同名与相邻前缀分别匹配；仅评论、已删除评论、dirty 和读取错误按规则处理 |
| 全量统计与错误 | 目录进度、评论及错误汇总保留完整范围；全局错误优先，不被空筛选结果替代。非全部下目录复选框与批量菜单关闭，单文件保留原校验 |
| 批量各入口 | 命令和 checkbox 接收时固定是否允许批量，执行时及进入存储提交前再次检查当前模式；旧目录、无目标整树命令不能借后来切回全部获得权限。目录成员全集与内容指纹校验未改变 |
| 导航与评论上下文 | 筛选使用独立队列，不递增导航序号、不替换当前对象与锚点；隐藏有效评论目标显式导航时恢复全部，可见目标保持模式。既有 CR、锚点与迟到结果保护仍在调用链中 |
| 扫描与兼容 | 筛选操作只重绘当前视图并写工作区偏好；不直接调用 Git 或全仓扫描，不修改评论、回执及交接范围。新增两个命令，既有命令、扩展 ID 和数据格式不变；`state.ts`、`model.ts` 无差异，锁文件只更新版本号，未增加依赖 |

批量提交的最后校验位于 [`state.record`](../../src/state.ts) 已取得仓库锁和 CR 锁之后，由 [`ReviewService.mark`](../../src/review.ts) 传入的回调先核对当前 CR，再检查筛选与 dirty 状态。筛选期间发起、排队后才执行，或等锁后才准备提交的批量请求会被拒绝。**通过该校验后，读取记录、写快照与保存记录仍有异步步骤；本实现不承诺随后切换筛选能撤销已进入提交或已落盘的操作。**

偏好保存失败不会发布成功的新模式。自动操作的补偿写入若也失败，会明确报错；此时不能声称持久值已恢复，后续成功的手动模式写入可恢复一致。
