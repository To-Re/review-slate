## 审核职责与边界

代码审核先确认基线、实际差异和调用者，检查内容新鲜度、状态一致性、失败恢复、资源生命周期及数据兼容。性能优化必须保留分支与 CR 归属检查，不能以过期内容、遗漏文件或错误的已审状态换取速度。

发现按影响排序，给出触发条件、实际影响、实现位置和最小修复方向；同一根因合并报告。审核者默认不修改实现，修复由客户端负责人完成，再依据实际候选复核。测试夹具只使用临时合成仓库。

本分支不评审其他客户端的运行时或数据布局。独立代码审核不代替 QA、真实编辑器验收、披露审核或发布授权；分别从[测试](../测试/README.md)、[设计](../设计/README.md)、[产品](../产品/验收条件.md)和[安全](../安全/README.md)查证。
