# 路线图

维护责任：项目负责人；最后核查：2026-11-03。下述 Codex 与 Harness 工作均未实现。

当前公开版本是 [1.0.1](../CHANGELOG.md)，已实现 VS Code 系编辑器内的持续审阅和本地文件交接。下一阶段优先做 **Codex 应用内的连续审阅**；各应用独立保存进度，首版不做跨宿主数据互通、同步或迁移。DeepSeek Harness 延后，没有承诺发布时间。

## Codex 下一阶段

目标是让用户在 Codex 内完成选择仓库与基点、浏览全仓变更、记录已审、写评论、交给 Agent 处理及人工复核，并在代码继续变化或应用重启后接续审阅。现有“复制交接说明”只是可复用的协作方式，不能代表这个目标已经完成。范围与验收条件见[产品规则](product.md)，宿主能力和技术选择见 [Codex 设计](codex.md)。

| 阶段 | 状态 | 下一步与交付物 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 验证最小审阅原型 | 待办 | 按 [Codex 原型门槛](codex.md#第一项开发任务验证真实宿主闭环)，在真实宿主安装原型；用合成仓库打开树和 Diff，保存文件评论与已审标记，再重启接续 | UI 动作能可靠读写独立本地状态，内容变化可复审，停用后无残留进程；六项原型门槛有实测结论，失败时明确能力缺口 |
| 完成连续审阅 | 待办，依赖宿主验证 | 复用已核实的核心逻辑，实现固定基点、全仓变更树、Diff、已审快照、复审和本应用独立存储 | 在目标 Codex 宿主完成“审阅 → 修改 → 复审 → 重启接续”，返回上次对象与导航位置；仓库、分支和 CR 隔离，错误不会被记成已审 |

| 验收并交付首版 | 待办，依赖前述功能 | 对照产品 AC，在实际 Codex 宿主验证安装、使用、恢复和异常，整理可分发产物与使用说明 | 产品验收有实际运行证据；必要的代码、安全与界面审核通过，兼容范围和未覆盖范围明确，发布另按授权执行 |

现有 VSIX 的自动化入口见[贡献指南](../CONTRIBUTING.md#验收矩阵)，可帮助复用核心规则，但不证明 Codex 的 UI、权限、重启恢复或完整用户任务可用。每阶段结果写回对应设计与本页状态，实际验证证据关联实现提交和目标宿主。

## 首版约束

- 保持轻量，不增加 HTTP 监听、后台守护进程、同步服务或额外部署步骤；宿主管理的 stdio 子进程是否适用，留待技术验证。不能满足这些条件的宿主方案需重新评估。
- 每个应用独立保存自己的 CR、已审快照、评论与进度。Codex 的存储边界按其设计实现，不与其他应用共写同一 `.code-review/` 命名空间，也不把它解释为完整进度交换格式。
- Git 保持只读；评论与引用代码是待分析数据，不扩大任务授权。Agent 回执与人工解决分开，路径、归属和版本不匹配时停止处理。
- 保持已发布 VSIX 的兼容性。共享核心逻辑与新增宿主适配不改变现有用户的数据归属；未来若需要网络或额外权限，须先明确用户可见的数据流。

## DeepSeek Harness

状态为**延后**。Codex 的核心审阅流程验证后，再核查 Harness 的安装、UI、文件访问和权限能力，并单独确定适配范围。沿用应用内独立存储与轻量运行约束；目前没有 Harness 专用插件，也没有宿主实测结论。
