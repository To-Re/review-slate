## 1.0.4：多仓库审阅记录

用户反馈：工作区同时打开 API、RPC 两个仓库，从 Git 图形为 API 新建 CR 后，RPC 的 CR 从“审阅记录”中消失。原因是记录只显示当前仓库，数据没有丢失。1.0.4 让多仓库工作区按仓库分组同时列出各仓库的 CR，点击即切换，条件见 [VSIX-AC-23](产品/验收条件.md#多仓库审阅记录验收)。安装入口为 [1.0.4 Release](https://github.com/To-Re/review-slate/releases/tag/v1.0.4)，发布对象以该页的公开附件为准。

## 持续维护边界

- `main` 只维护 VS Code 系 VSIX；Codex 的进行中工作保留在 [beta](https://github.com/To-Re/review-slate/tree/beta)，不整分支合并。
- 当前版本保留扩展 ID 和既有命令，1.0.3 新增筛选入口，1.0.4 新增“切换到此仓库”，不更改已有审阅数据格式或存储位置。
- 后续性能优化继续核对内容新鲜度和分支、CR 归属，不通过清空进度或省略校验提速。
- 有评论空态、定位代码按钮、未保存和读取失败的真实界面、完整关闭重开、其他主题及 VS Code / Trae / Remote SSH 的实机覆盖仍待补齐；现有定向结果不扩大为全部兼容性保证。
- 文档按一个角色一个目录维护，替换旧稿并修复引用，不保留过期副本。
