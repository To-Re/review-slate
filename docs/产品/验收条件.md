# VSIX 产品验收条件

维护责任：产品负责人；状态：现行；最后核查：2026-11-04。适用范围：`main` 的 VS Code 系 VSIX。本次核对以 `eba6bbf` 为基线的 1.0.3 及新增变更树筛选条件 `VSIX-AC-16～22`。业务定义见[业务规则](业务规则.md)，实际运行证据由[QA](../测试/验证记录.md)维护，实际发布状态见[项目现状](../项目现状.md)。

使用 `VSIX-AC-*` 标识本分支条件，避免与其他客户端的目标混用。以下是可判定预期，不是通过声明。每次验收绑定提交或 HEAD 加未提交差异、宿主及系统版本、数据规模、方法和结果；通过、失败、未执行、阻塞与不适用分开记录。

## 功能与连续性

| ID | 用户结果 | 可观察的通过条件 |
| --- | --- | --- |
| VSIX-AC-01 | 仓库与基点明确 | 从子目录进入仍识别正确 Git 根目录，多仓库设置隔离。分支来源取共同祖先，提交来源取自身并固定完整 SHA；有效完整或至少 7 位短 SHA 可用，无效、歧义、无共同祖先或无提交时不创建成功记录。取消或修改默认基点不改变当前 CR |
| VSIX-AC-02 | CR 复用和分支隔离 | 同仓库、同分支、同基点复用未归档 CR，保留 ID、进度和评论；其他组合独立。切回分支接续最后 CR，打开其他分支的记录提示先自行切分支，不自动 checkout |
| VSIX-AC-03 | 变化完整且进度准确 | 全部模式的树覆盖固定基点之后的提交、暂存、未暂存和未忽略新文件，排除工具自身数据。父目录正确汇总部分/全部已审和后代评论，仅评论对象不增加变化文件分母；筛选只改变显示，刷新、折叠和展开不改变已审内容 |
| VSIX-AC-04 | 已审对应确定内容 | stage / commit 后内容未变仍已审；单文件内容、类型或权限变化需复审，恢复已审内容可重新匹配。未保存、读取失败、旧指纹或批量目录成员变化时拒绝误标；取消标记只影响指定范围，不删除评论 |
| VSIX-AC-05 | 完整 Diff、可编辑右侧与复审可用 | 从树打开正确文件，左侧为固定基点，右侧对应工作区；普通 UTF-8 文本可在右侧编辑并由编辑器保存。未保存状态清楚且不能标已审；保存后重新打开得到当前内容。上次已审增量比较正确，无快照时明确提示；删除、二进制、非 UTF-8、链接与模式变化有正确表示 |
| VSIX-AC-06 | 评论对象和版本可信 | 文件、目录、完整 Diff 两侧选区的评论保存后可读取；编辑保留 ID 并更新版本，取消不新增。超限或保存失败不丢已填内容。删除可恢复，解决不改变文件已审；修改或重新打开后旧回执不再代表当前版本 |
| VSIX-AC-07 | 定位和意见汇总可靠 | 片段唯一匹配时可随行移动；内容改变、重复片段或路径消失时保留原片段并显示准确状态，不猜测确定位置。没有 Diff 的遗留评论仍可访问。父目录和待处理概览正确聚合并能处理意见，切 CR 不串计数 |
| VSIX-AC-08 | Agent 交接保持人工控制 | 交接只复制固定仓库、CR、分支、基点和评论版本的说明，不启动 Agent。匹配回执显示待复核，由人解决；切 CR 不改变原交接目标。已归档、删除或归属不符时停止对应处理，远程路径和执行位置明确 |
| VSIX-AC-09 | 保存与恢复不串对象 | 重建服务或重开项目后可读取已保存 CR、进度、快照、评论和回执；草稿按现有宿主状态范围核对，不保证完整导航恢复。切换仓库、CR、分支后旧页面不能误写；写入失败、损坏、缺失和并发冲突明确失败，不清空或静默覆盖原数据 |
| VSIX-AC-10 | 归档、恢复和永久删除边界清楚 | 归档可恢复，同组合冲突保留双方；永久删除确认明确目标和不可恢复范围，取消无变化。中断按已持久化阶段提供恢复或重试，完成后其他 CR、代码和 Git 元数据不受影响，旧页面与交接不能复活已删数据 |
| VSIX-AC-11 | 兼容与运行边界保持 | 扩展 ID、命令、URI 和既有数据格式兼容；受信任桌面工作区可运行，VS Code、Trae、Trae CN 分别记录验证范围。Git 保持只读且不执行过滤器或外部 diff，不跟随存储符号链接，不新增网络上传、遥测或常驻服务；失败不冒充成功 |

## 变更树筛选验收

本次只验证树筛选及受影响的状态、导航和写入保护，不增加组合筛选或评论状态条件。使用合成仓库，准备已审、待审、需复审、未保存、读取失败、仅评论、仅已删除评论及深层目录对象；评论至少覆盖文件、选区、目录、已解决和待复核。自动化与真实宿主分别判断，未执行的场景不沿用此前版本的通过结论。

| ID | 用户结果 | 可观察的通过条件 |
| --- | --- | --- |
| VSIX-AC-16 | 模式可辨认且可恢复 | 单一入口只提供互斥的全部 / 未审核 / 有评论，默认全部，取消不改模式。非全部明确显示当前模式，并可一键显示全部；空结果保留基点和可用恢复入口，整体读取失败仍显示错误，不能伪装成无匹配 |
| VSIX-AC-17 | 未审核集合准确 | 待审、需复审、读取失败和当前树中的未保存变化文件显示；有效已审且无错误、无未保存修改的文件隐藏。仅评论及仅已删除评论对象不命中。标记成功后文件隐藏，后续内容变化或未保存时恢复显示，保存后按实际内容重新判断 |
| VSIX-AC-18 | 有评论集合与路径准确 | 文件 / 选区评论命中文件，目录评论命中目录；未解决、待复核、已解决均显示，已删除和单独回执不命中。只保留命中对象及祖先；目录自有评论不放出无评论后代，同名文件 / 目录和相邻前缀不串用。没有 Diff 或路径消失的保留评论可访问；解决不隐藏，删除最后一条后隐藏，恢复后显示 |
| VSIX-AC-19 | 隐藏成员不被批量修改 | 非全部时目录 / 整树 checkbox、标记和取消已审入口不可用；陈旧目录节点与无目标命令也不能绕过。批量请求在接收、执行、取得写锁后进入持久化前检查筛选，任一检查不满足即拒绝且记录不变；已通过最后检查进入持久化的操作不承诺因后来切模式撤销。单文件照常校验，切回全部后原有完整刷新、指纹和目录成员保护有效。全局及目录进度、评论与错误汇总保持全量口径，并说明包含隐藏项 |
| VSIX-AC-20 | 偏好与数据归属独立 | 同工作区切换 CR、分支或仓库保留模式，但仅显示当前对象数据；重开同工作区恢复。其他工作区默认全部，缺失或非法值回退全部；保存失败保留原显示并报错，连续选择按顺序保存。不修改既有 CR / 评论格式、清空进度或共享跨宿主状态 |
| VSIX-AC-21 | 筛选后仍能继续审阅和定位 | 改模式或匹配集合变化不关闭 Diff、不清评论对象 / 选区 / 草稿。明确导航到被隐藏的有效对象时，切全部并给出模式变化反馈，然后正确打开、选中和定位；可见目标不重置模式，普通标签切换也不重置。陈旧 CR、无可靠锚点或消失对象保持原错误保护 |
| VSIX-AC-22 | 筛选不退化为扫描或缩小任务范围 | 仅切模式、清除和取消操作不新增 Git / 全仓扫描；不改变已审、评论、回执或交接清单。正常刷新、评论操作与 dirty 变化后重新匹配；筛选不限制评论区、待处理概览或交接范围。连续切模式与文件、后台刷新交叠后仍对应用户最后一次有效导航；排队的自动清除需重查目标与可见性，过期导航或已可见目标不覆盖当前模式 |

QA 验证命中集合、持久化、命令保护和调用计数；真实宿主核对入口、当前模式、空态、目录禁用、隐藏目标定位及草稿连续性。模拟状态不能代替真实树与菜单；无须为了纯内存筛选重复无变化的三轮大仓基线。

## 首次变更树和点击 Diff 的性能验收

性能测量使用临时合成仓库与虚构评论。先明确计时边界，再比较同一环境的 `3dd7e30` 基线与最终候选；不能用测试的延迟模拟值或单次最快值证明用户体验。

| ID | 关注点 | 可判定条件与证据要求 |
| --- | --- | --- |
| VSIX-AC-12 | 首次选基点后生成树的等待改善 | 使用尚无 CR 的独立合成仓库，从基点确认或对应命令开始，测到首次完整文件树数据可用；注明是否包含提交选择 UI 和真实树绘制。基线与候选的文件数、变化数、内容量和冷/热状态一致，多轮报告耗时、中位数和范围，并核对实际列出的变化集合。已有 CR 的热刷新不能抵扣首次创建；不得提前显示成功而遗漏扫描或 CR 校验 |
| VSIX-AC-13 | 打开 Diff 的等待得到针对性改善 | 在相同文件数、变更数、内容量、已审记录和评论规模下，对普通热点击与后台刷新在途时点击分别多轮测量；拆开命令排队等待、扩展处理至发出 `vscode.diff` 请求及命令总耗时。报告每轮结果、中位数和范围；候选对已定位瓶颈减少可解释的工作量并呈现一致改善，未改善或有退化的场景明确保留结论，不设未经测量的毫秒或比例承诺 |
| VSIX-AC-14 | 提速后仍展示正确的新鲜内容 | 连续点选不同文件、重复打开同文件、磁盘保存后重开、树显示后内容或类型改变、分支或 CR 切换时，Diff、评论对象与用户最后一次仍有效的选择一致；内容已变化时重新读取或明确要求刷新，不把旧缓存当当前内容。首次树与后台刷新也不得遗漏变化；未保存保护、完整/增量来源、选区归属及读取失败仍符合 VSIX-AC-04～09 |
| VSIX-AC-15 | 真实等待体验与整轮任务单独核对 | 在明确版本的真实目标宿主中，从选择基点至完整目录树可用、从树点击至可读 Diff，核对等待、连续切换、编辑保存、复审和评论接续；必要时记录界面时间或视频。模拟 TreeDataProvider 或 `vscode.diff` 返回只证明扩展调用路径，不能证明原生树/Diff 已绘制、窗口无卡顿或完整产品任务通过 |

测量记录至少说明系统、Node/Git 或真实宿主版本、基线与候选指纹、合成样本生成方式、冷/热状态、重复轮次及是否存在后台刷新。刷新、标记、保存触发刷新是关联回归，不代替两个主路径。Git 调用次数、内容读取次数等确定性证据用于解释改进；不通过跳过内容、归属、损坏或写入保护换取速度。

VSIX-AC-12 和 VSIX-AC-13 都需要可复现的前后测量与瓶颈解释。实测不足以确认改善时写未验证；已执行且结果相反时写失败或保留具体退化，不能在执行后随意更换场景使结果显得通过。

## 完整用户任务

QA 的相关检查通过后，在同一候选运行下列连续任务；产品依据可核查结果判断对象、规则和恢复路径，设计另行核对实际界面。需要真实宿主的步骤未执行时保留对应缺口。

1. 进入尚无 CR 的合成仓库，选固定基点，创建 CR，确认完整变更树、仓库与当前分支。
2. 连续点击深层目录中的不同文件查看完整 Diff，分批标记已审，保存文件、目录和选区评论；确认树进度与评论对象对应。
3. 在完整 Diff 右侧修改、保存，重新打开并复审；做内容不变的 stage / commit，确认进度保持。再只改一个文件，确认其增量与其他文件状态。
4. 切换分支建立独立 CR，再切回；重开项目，核对保存数据。核查陈旧页面、未保存文本或磁盘变化不会认证错误内容。
5. 复制指定 CR 的交接说明，用合成回执验证待复核与人工解决；编辑或重新打开意见后确认旧回执失效。
6. 验证取消、读取/保存失败和恢复；归档、恢复及确认永久删除时核对影响范围。
