## 适用方法

使用临时合成 Git 仓库、虚构评论和受控测试数据，覆盖正常路径、取消、恢复及归属变化。每项结果绑定同一候选版本、未提交差异、目标宿主版本、操作方法和证据。自动化可验证业务规则，真实宿主负责界面、权限、安装与生命周期；两者不能互相替代。测试场景与执行记录由[QA](../测试/README.md)维护。

本轮选择及来源见[首版设计选择](README.md#codex-首版的设计选择)。AC-10 采用固定交接说明、用户在 Codex 会话发送；AC-12 的评论草稿与导航范围已经落定。**0.1.x 本地候选按只读 Diff 核验 AC-06**：完整/增量 Diff、来源、选区与复审继续适用；仅代码编辑、显式源码保存及代码恢复副本条件项不适用，因候选明确不提供它们，后续随 E1 实现与验证。不能将 AC-06 整项记为不适用或通过，也不能把未提供编辑写成已完成。AC-11 的评论、进度与草稿可靠保存等要求不受此取舍影响。

## 验收矩阵

| ID | 用户结果 | 可观察的通过标准 |
| --- | --- | --- |
| AC-01 | 仓库选择、切换和对象归属明确 | 首次无仓库时有明显入口，已有仓库时顶部持续显示当前项目并可切换；系统窗口单选文件夹，最近项目直接打开，手动路径默认折叠备用。选择后直接校验，不要求复制路径或重复确认；子目录解析正确 Git 根目录，系统选择返回的空格路径保持原值，最近记录仍重新核对权限。等待时防重复选择；取消或迟到结果不切换项目、不改变草稿和最近记录。跨仓库返回各自的分支和最后有效 CR，设置、进度、评论、草稿及导航不串用；无 CR 显示新建。目标无效时错误归属候选路径，保留重选，失败目标不加入最近列表；关闭弹窗可继续原审阅，不能误禁用原仓库或以旧树冒充目标成功。旧草稿保存失败、连接中断和结果待核对仍阻止切换 |
| AC-02 | 选择稳定且不误变的基点 | 分支来源取共同祖先，提交来源取自身；分支或 `HEAD` 移动不改变已选基点。超过 150 个提交的仓库中，可选择列表外完整和至少 7 位短 SHA；无效或歧义输入可改后重试。取消不改变当前 CR，修改默认不改变当前基点 |
| AC-03 | 复用正确 CR 并继续审阅 | 已有记录时仍可找到新建入口。同分支同基点重新选择后 ID、进度和评论保持；不同分支或基点分别保存。同仓库多 CR 切换保留各自对象、评论草稿与导航，失败不覆盖原记录；切回分支和重开项目接续最后使用的 CR，打开错误分支记录时不自动 checkout |
| AC-04 | 看全变化与目录部分进度 | 合成仓库包含深层目录、分支提交、暂存、未暂存及未忽略新文件，树完整列出保存后的变化，排除被 Git 忽略的未跟踪文件及工具自身数据。勾选部分文件后祖先显示准确的部分已审数量；全部已审后才显示已审完，折叠和展开不丢进度 |
| AC-05 | 进度跟随内容而非 commit 次数 | stage 或 commit 而内容不变时保持已审；单文件内容、类型或权限改变只使对应文件需复审；恢复原内容可重新匹配。未保存、读取失败、陈旧页面或目录新增文件不能被误标已审；取消标记只影响指定范围 |
| AC-06 | 查看完整 Diff 与审阅后增量 | 从树进入明确标注两侧来源的完整 Diff；新增、删除及受限内容有可理解表示。标记后再修改，能查看上次已审内容到当前内容的差异。说明并验证保存方式，不能把未落盘文本当作已保存版本；是否支持 Diff 内直接编辑由宿主核验后决定。提供编辑时，显式保存、外部改动冲突与写入结果不确定均有可验证处理，不能自动覆盖或自动标已审 |
| AC-07 | 保存三类对象的评论 | 在目录、文件和选区分别保存意见并可重开查看；选区明确所属侧，原片段可见。编辑保留 ID，取消编辑不新增；删除可恢复，解决不改变文件已审状态。超出选区或内容限制时明确失败且不丢已填内容 |
| AC-08 | 代码变化后仍能正确理解意见 | 在原片段前插入行后可定位唯一匹配位置；代码改变、重复片段、路径删除或改名时保留原评论和片段，显示准确定位状态。无法可靠定位时不提供错误的确定跳转；没有 Diff 的遗留评论仍可访问 |
| AC-09 | 目录与概览完整聚合意见 | 父目录折叠后仍计入本目录及所有子项评论，区分未解决和已解决。目录评论不计作变化文件；待处理概览可跳到对象并处理。解决、删除、恢复后汇总及时一致，切换 CR 不残留另一轮计数 |
| AC-10 | Agent 处理后由人复核 | 用户预览当前 CR 范围后复制固定交接并在 Codex 会话发送；取消不改变状态，复制不冒充 Agent 已接收。接收方得到明确的仓库、CR、分支、基点和评论版本。匹配回执显示待复核，由用户决定解决；修改或重新打开意见使旧回执失效，已有待复核意见不默认重做。切换 CR 后原交接不转向另一轮；归属不符或记录失效时停止处理 |
| AC-11 | 保存与错误恢复可信 | 保存成功后关闭重开恢复基点、已审快照、评论和回执；模拟写入失败、中断、损坏与并发更新时，不报告虚假成功、不覆盖原数据。错误修复后能够重试，恢复不要求先清空进度 |
| AC-12 | 草稿和导航可以接续且不串对象 | 切换对象、CR、仓库或关闭重开后，返回本轮可接续原审阅对象、目录展开和 Diff 定位上下文；原对象失效时有准确提示及可用恢复入口。新评论及原评论编辑草稿按[声明范围](业务规则.md#6-保存草稿与应用内接续)恢复，包含完整选区上下文，失配不变更评论类型、不串对象；未提交与本地保留结果明确。编辑方案启用时，恢复代码缓冲不自动写盘，磁盘冲突保留输入。旧页面在分支或 CR 改变后不能向新记录保存或错误定位 |
| AC-13 | 归档和删除的边界清楚 | 归档后原数据保留且可恢复；同组合的新旧记录冲突时双方保留。永久删除前明确对象与影响，取消无变化；中断后显示可重试状态，完成后其他 CR、工作区代码和 Git 元数据保持，旧交接与页面不能复活被删数据 |
| AC-14 | 各应用独立持久化且互不覆盖 | 同一合成仓库分别用编辑器与 Codex 创建、标记和评论；各自重开能恢复自身状态，一端操作不改写另一端的 CR、快照、评论、清单或回执。Codex 不共同写入编辑器已有 `.code-review/` 范围，不宣称跨应用接续；无需实现共享、同步或迁移 |
| AC-15 | Git、权限及轻量运行符合约束 | 审阅操作不 fetch、checkout、提交或写索引，不触发仓库过滤器、external diff 或自动对象下载，不跟随存储符号链接。无权限时明确失败，用户可在宿主授权范围内恢复。无需新增常驻服务器或 HTTP 服务部署，无需另开模型账号；交给 Agent 时明确资料范围及执行位置 |
| AC-16 | 在 Codex 内完成整轮人工审阅 | 在真实 Codex 桌面安装后，从明显入口完成选仓库、固定基点、全仓变更查看、分批已审、三类评论、交给 Agent、读取回执、复审及关闭重开接续。核心人工审阅不要求跳到另一编辑器；CLI 输出、自动审查报告、skill 读取评论或模拟界面不能判此项通过 |
| AC-17 | 中英文界面可切换且不影响审阅 | 两种界面均能完成同一审阅任务，导航、动作、状态、空态、校验、错误摘要与恢复、确认和可访问名称完整且含义一致。无手动偏好时，宿主 `zh`/`zh-*` 使用简体中文，其他、缺失或无效 locale 使用 English；可手动选简体中文、English 或跟随宿主，偏好在本地跨仓库/重开保持。偏好写入失败维持原语言并可重试。切换保留当前 CR/对象、导航、已审/评论/回执、新建与编辑评论草稿、选区及已有代码缓冲；用户内容、路径、分支、提交信息、ID/revision 字节不变，不自动提交或调用在线翻译 |

AC-14 的双应用场景用于证明隔离，不是要求同步或互相读取。AC-15 的“不另开模型账号”指不增加 ReviewSlate 专属模型服务要求，不免除宿主自身已说明的正常使用条件。

AC-01 的系统单文件夹选择、最近项目和 AC-17 的中英支持来自用户确认；简体中文、locale 回退、应用级偏好及失败时保留旧语言是产品细化。验收使用至少两个合成仓库和同仓库两条 CR 检查相同相对路径不串数据；系统选择覆盖取消、重复点击、GoTo、空格路径、非 Git 后继续原任务及重新选择。语言覆盖 `zh-CN`、`zh-TW`、`en`、其他及缺失 locale，并在留有两类评论草稿时切换，编辑能力启用时再包含代码缓冲。系统标准控件沿用系统语言，插件提供的标题、说明和确认动作按当前界面语言检查。不沿用此前设计通过结论替代新包运行证据。

## 完整任务如何验收

单项自动化与接入验证完成后，在同一真实 Codex 候选版本执行以下连续任务，检查功能之间是否仍保持对象和状态。它是 AC-16 的产品体验方法，不另立一组需求或用例编号。

1. 从首次无仓库状态经明显入口打开系统窗口，选择一个合成项目文件夹，选择固定基点，新建 CR。确认当前对象、比较范围和明显的历史入口；检查两种界面均可操作，并确认备用手输入口可发现。
2. 查看深层目录中的完整 Diff，分批标记文件，保存文件、目录和选区意见。折叠父目录，核对进度和评论聚合。
3. 按候选版本声明的方式保存代码，再由测试执行者在合成仓库 commit；ReviewSlate 不执行提交。内容不变时确认已审仍在；只改一个文件，查看该文件上次审阅后的变化，确认其他已审文件保持。提供直接编辑时，另检查未保存不能标已审、外部改动不能被默认覆盖。
4. 切到另一分支建立独立 CR，再切回；从顶部切到第二仓库，再经最近仓库返回，核对各仓库及 CR 的对象、评论和导航。留下新评论、编辑草稿和选区上下文后切换中英文，关闭并重新打开，确认偏好及数据分别接续；编辑能力启用时同时检查代码恢复副本，重开只恢复到缓冲，工作区磁盘不能被自动修改。
5. 预览当前 CR 的范围并复制交接，由用户在 Codex 会话发送；复制后不显示 Agent 已处理。取得匹配回执后查看修改、人工复审和解决。编辑或重新打开一条意见，确认旧回执不能表示本次处理完成。
6. 留下草稿后取消系统选择，再选择非 Git 目录；关闭错误弹窗后继续原审阅，确认不需要重选原仓库或重写草稿。在合成数据上触发真正保存失败、陈旧页面写入、对象消失及语言偏好写入失败，确认保护仍生效、原数据保留及恢复路径；核查归档、恢复和永久删除的边界。

执行者记录实际结果及需手动补救的位置；没有合适候选版本或宿主无法访问时写未执行或阻塞，不用口头推演替代操作。设计角色另行检查界面体验，QA 通过不代替产品或设计验收。
