# Codex 数据、隐私与故障处理

> **beta / WIP：Codex 0.1.2 仍在开发中。** `beta` 源码公开不代表安装包正式发布；真实 Codex 宿主和整体体验验收尚未完成。

适用范围：ReviewSlate Codex 0.1.2 只读开发候选版，实际验证范围见[验证记录](../测试/验证记录.md)。维护责任：写作；最后核查：2026-11-03。操作入口见[Codex 使用指南](Codex使用指南.md)；本文依据[客户端数据协议](../客户端/数据协议.md#codex-独立存储方案)与[客户端实现](../客户端/Codex客户端方案.md)。VSIX 使用另一套位置，见[VSIX 数据说明](数据与故障处理.md)。

## 保存位置与应用边界

| 位置 | 保存内容 |
| --- | --- |
| 仓库根 `.reviewslate/codex/` | CR、默认基点、已审记录与代码快照、评论与回执、删除恢复区、完整评论草稿、导航、固定交接批次及操作记录 |
| macOS 用户目录下的 `Library/Application Support/ReviewSlate/Codex/` | 界面语言、最近仓库、上次仓库标识及跨仓库操作核对记录；不含评论草稿正文 |

只有首次启用保存时才建立仓库内的数据目录，并按需向根 `.gitignore` 追加 `/.reviewslate/codex/`，保留原有规则。已经被 Git 跟踪的文件不会因此取消跟踪，提交前仍需检查。数据目录已被其他内容占用、标识不符、格式不受支持或路径包含不允许的符号链接时，会停止写入。

Codex 不读写 VSIX 的 `.code-review/` 或编辑器扩展存储；两种应用的进度和评论互相独立，没有同步、导入或迁移功能。仓库身份包含实际根路径，linked worktree 各自独立；移动或复制仓库后，原数据可能因身份不符而不能接续，不能靠改标识强行关联。

资料不放在插件安装目录或缓存中，升级或卸载插件不等于删除审阅记录。草稿保存成功只表示本地保留；未确认保留的输入可能仍只在当前页面中，不能按“已经有数据目录”判断它已保存。

0.1.2 性能修复不改变数据目录或格式，也不增加服务器。已有进度、评论与已保存草稿继续保留，无需迁移或清空数据。

## 代码与资料怎样流动

插件本地运行时不联网、不上传代码、无遥测，没有 HTTP 监听服务；页面通过宿主管理的本地工具通道访问仓库。Git 调用保持只读，不执行 fetch、checkout、提交或索引写入。当前 Diff 只读，代码修改由你在编辑器或授权的 Agent 中完成。

ReviewSlate 仍会按你的操作写入审阅数据，首次启用还会追加上述 `.gitignore` 规则。“只读 Git”不表示完全不写磁盘。

系统文件夹选择器只在你点击“选择文件夹…”时运行，完成或取消后退出。选择文件夹本身不建立审阅数据；应用随后校验仓库，只有首次新建审阅确认启用保存时才创建数据目录。取消或选择的目录无法作为仓库打开时，当前项目保持不变，也不会自动初始化 Git。

数据文件未加密。已审快照包含代码，选区评论及草稿包含原片段，交接说明包含本地路径。备份应按代码资料保管，不要直接上传整个数据目录、原始日志或真实项目截图。

普通浏览不自动生成 Agent 任务，“交给 Agent”只生成并复制说明。你自行发送后，接收方如何处理资料取决于该服务与授权。代码和意见通过组件专用通道传递是当前协议设计；真实 Codex 宿主中的最终资料边界仍需验收，不能据此承诺宿主无法访问资料。

## 备份与恢复

当前没有一键导出、跨应用迁移或自动修复损坏数据的功能。备份前，等待页面确认导航与草稿已在本地保留，然后停止相关插件进程及 Agent 写入。

1. 完整复制对应仓库的 `.reviewslate/codex/`，包括备份、操作记录与永久删除标识。
2. 如需保留语言、最近项目和操作核对信息，同时复制上表中的用户应用数据目录。它不能替代仓库内的审阅资料。
3. 另行备份需要保留的 Git 对象与未提交文件。已审快照只覆盖审阅时保存的内容，不是完整仓库备份。

恢复前先保留当前副本，停止所有相关写入者；在相同仓库路径、兼容客户端下恢复同一时点的资料，重开后核对仓库、分支、完整基点、CR、已审数和评论归属。移动路径、换应用或跨机器自动接续不在当前能力范围内。

单个 `.bak` 可能只是某个文件的上一版本，不能证明它与其他文件、快照或删除状态一致。不要删除损坏 JSON 来创建空进度，也不要只恢复一份旧评论或移除永久删除标识。需要人工恢复时按[数据协议](../客户端/数据协议.md#codex-独立存储方案)检查关联资料。

单条评论删除可恢复，归档可恢复；永久删除进入删除标识已保存的阶段后，只能继续清理。永久删除不会擦除你另存的备份或系统缓存，不属于安全擦除。

## 比较与容量限制

| 情况 | 当前处理 |
| --- | --- |
| 大文件 | 单侧变化文件上限 5 MiB；一次扫描的变化文件两侧累计上限 80 MiB |
| 二进制、非 UTF-8、符号链接、类型或权限变化 | 按可读取内容或摘要展示；不提供普通代码编辑。符号链接不跟随目标 |
| 子模块 | 需要单独作为仓库审阅 |
| Git LFS、换行规范化及其他过滤器 | 按原始磁盘字节比较，不执行 clean、textconv 或 external diff，结果可能与其他 Git 界面不同 |
| 评论 | 正常评论区与已删除恢复区各最多 2,000 条，跨 CR 计数；已解决也计入，归档不释放条数 |
| 评论草稿 | 每份视图最多 200 条，每条正文最多 20,000 个 JavaScript 字符单位；整份保存文件还受 16 MiB 限制 |
| 代码选区 | 1–200 行；选区与上下文另有长度限制，超限时改用文件意见或缩小范围 |

合并冲突、读取失败、损坏快照或超限会显式报错，不能据此判定“没有变化”或“已经审完”。修复原因后再刷新确认。

## 遇到问题时

| 情况 | 处理方式 |
| --- | --- |
| 插件无法启动 | 核对是否为 Apple Silicon Mac、包是否完整、系统 Git 是否可运行。当前以 macOS 13+ 为目标，最低版本兼容性仍待实测。完整包无需另装 Node.js；开发用的无运行时 bundle 不能当安装包 |
| 看不到“选择文件夹…”等新入口 | 先核对本机已安装版本。0.1.0 不包含该入口；更新源码或重新打包不会自动更新已安装插件，安装方式与验证边界见[接入记录](../客户端/Codex接入.md) |
| 更新后仍加载旧版本 | 确认已安装 0.1.2，等待“导航与草稿已在本地保留”后完全退出并重开 Codex；只关闭面板可能仍沿用旧版进程 |
| 大型仓库打开或刷新较慢 | 0.1.2 的单文件 Diff 和草稿保存不再等待全仓扫描；首次打开、完整刷新和标记已审仍可能耗时。[合成仓库基准](../测试/验证记录.md#2026-11-03-大型-idl-仓库性能验证)不包含真实 Codex 面板耗时 |
| 系统文件夹窗口未能打开或选择已超时 | 按提示重试；也可展开“手动输入路径”，填写本地仓库目录。另一个选择窗口仍开着时，先完成或取消它 |
| 文件夹选择连接中断 | 使用“重试选择文件夹…”核对原选择结果，或取消选择。关闭项目弹窗后，迟到的选择结果不会打开项目；当前 CR 和草稿仍需按原保存状态处理 |
| 所选文件夹不是 Git 仓库、无法打开或最近项目失效 | 使用“重新选择文件夹…”选取可访问、至少有一个提交的 Git 项目；手动路径有误时保留输入并修正。原项目保持不变，最近记录不授予额外权限 |
| 代码改了，Diff 没变化 | 先在编辑器保存，再从“变更文件”处刷新；外部编辑器未保存内容不属于当前比较 |
| 提示文件内容已变化，无法保存评论或标记已审 | 刷新整轮变化，复核当前内容后再提交；单文件 Diff 已更新不表示整轮列表已刷新 |
| 草稿显示尚未保留或保留失败 | 保持页面打开，修复权限、空间等问题，再“重试保留”。若出现“导出当前草稿…”，可将完整草稿与归属复制到自行选择的本地文件；打开导出框本身不等于已经保存 |
| 分支或 CR 已变，页面显示上次结果 | 先“重新连接并核对”。有相应入口时，使用“保留原 CR 草稿并打开当前分支”，等原归属草稿保存确认后再切换；不能把旧草稿直接写入新 CR |
| 提示另一窗口已更新评论或内容 | 保留输入，核对当前记录、评论版本与选区。旧编辑不会自动变成新评论，也不会覆盖另一窗口的新版本 |
| 操作显示“结果待确认”或部分数据已落盘 | 不重复提交。先“重新连接并核对”原操作，按结果使用“核对并继续…”；没有查明前，不把失败提示理解为完全未写入 |
| 语言切换失败 | 原语言保持，输入保留。检查错误原因后重新保存偏好，不以当前下拉选择判断保存成功 |
| 评论定位失配或文件改名 | 查看原片段并人工确认当前位置；不会按旧行号猜测或自动迁移评论 |
| 保存资料无法校验或格式不受支持 | 保留主文件、备份与现状副本，停止相关写入并检查兼容版本；不清空数据重新初始化 |
| 本地保存被占用 | 先等另一操作结束。只有确认相关进程和 Agent 已停止、没有在途写入后，才按数据协议处理残留锁；不按等待时长自动删锁 |
| 永久删除未完成 | 从对应记录使用“继续永久删除…”，不删除标识强行恢复 |

仍无法解决时，在 [Issue](https://github.com/To-Re/review-slate/issues) 提供插件版本、Codex 与系统版本、架构、可重复步骤及脱敏错误文本，并说明问题出现在源码、完整包、独立测试宿主还是实际 Codex。优先用合成仓库复现；安全问题按 [SECURITY.md](../../SECURITY.md) 报告。
