# 数据、隐私与故障处理

适用于 ReviewSlate 1.0.1 VSIX；由写作角色维护，最后核查于 2026-11-03。日常操作见[使用指南](使用指南.md)，准确的数据布局与写入约定见[客户端数据协议](../客户端/数据协议.md)。

Codex 候选版使用独立的 `.reviewslate/codex/`，见 [Codex 数据与故障处理](Codex数据与故障处理.md)；不能用本页的两处 VSIX 数据恢复 Codex 进度。

## 先分清两处已保存数据

| 保存位置 | 主要内容 | 需要知道的边界 |
| --- | --- | --- |
| 宿主提供的 ReviewSlate 扩展存储 | 默认基点、CR 目录、已审记录、内容快照 | 按仓库实际根路径区分；扩展安装目录不是这个数据目录 |
| 仓库根 `.code-review/` | 已保存评论、Agent 回执、可撤销删除的评论、交接清单和删除标识 | 不包含完整 CR 目录或已审进度，不能单独用来恢复一轮审阅 |

此外，仓库选择与评论草稿等界面状态由编辑器保存。未提交草稿不等于已保存评论，也不保证包含在上面两处备份中；需要保留的正文应先保存为评论。

完整审阅依赖两处数据共同确定归属。只把 `.code-review/` 复制到另一台机器或另一个编辑器，既不能恢复已审标记，也不保证新宿主能把原评论接到正确 CR。不同编辑器、本地与远端扩展宿主各自保存数据，没有自动同步、导入或迁移工具。移动仓库目录或打开另一个 worktree，也会进入不同的存储分区。

## 本地保存与分享范围

扩展运行时不联网、不上传代码、无遥测，也没有 HTTP 监听服务。它通过只读 Git 获取比较所需资料，不执行 fetch、checkout、提交或索引写入。你在 Diff 右侧编辑并保存时，会实际修改工作区代码。

首次保存评论时会创建 `.code-review/`；首次保存或接续已有评论时，扩展按需向根 `.gitignore` 追加有效的 `/.code-review/` 规则，保留原有内容。已经被 Git 跟踪的数据不会因此取消跟踪，应自行核对准备提交的内容。已有非空 `.code-review/` 若不是有效的工具目录，扩展会报错而不会覆盖它。

这些文件未加密。快照保存审阅过的代码，评论可能包含原片段，交接说明与清单包含仓库及目标文件的绝对路径。备份应按代码资料保管；公开 Issue、日志或截图前，应去掉真实代码、内部信息和个人路径。不要直接上传整个 `.code-review/` 或扩展存储。

“交给 Agent”不会替你发送资料。你把说明粘贴给某个服务或工具后，资料怎样处理取决于那个接收方；远程路径还要求接收方能访问相应远端文件系统。

## 备份与恢复

当前没有一键导出或跨应用迁移功能。备份前，先保存需要保留的评论，并停止访问这些数据的扩展宿主与 Agent 写入任务。

1. 按扩展 ID `to-re.code-review` 定位当前宿主分配的扩展存储，完整复制该扩展的数据目录。实际位置由编辑器和本地／远端宿主决定。
2. 在同一时点完整复制对应仓库的 `.code-review/`，保留 `.bak` 备份和永久删除标识等辅助文件。
3. 若还要恢复当时的代码，另行备份 Git 对象和未提交文件。已审快照只保存审阅所需内容，不能代替仓库备份。

恢复前先保留现状副本，并停止所有相关写入者。恢复同一时点的两处数据后，在相同宿主、相同仓库路径下重开，核对分支、固定基点、CR、已审数量与评论归属。跨机器、换编辑器或移动路径不属于自动恢复能力；需要变更这些条件时，先按[数据协议](../客户端/数据协议.md)检查身份与存储边界。

单条评论删除可以撤销，CR 归档可以恢复；CR 永久删除不能在扩展内撤销。永久删除不会清除你另存的备份、编辑器历史缓存或所有旧草稿，也不是磁盘安全擦除。

永久删除在保存删除标识前失败，记录可能仍在“已归档”，可以恢复或重试；删除标识保存后发生清理失败，则进入“删除未完成 · 可重试”，只能继续清理。以实际分组与错误信息为准，不通过手改标识文件恢复记录，也不要只把一个旧评论或一份旧目录备份拷回去。阶段边界见[数据协议](../客户端/数据协议.md)。

## 比较与容量限制

| 情况 | 当前处理方式 |
| --- | --- |
| 较大的变化文件 | 单侧上限 5 MiB；一次扫描中变化文件两侧内容累计上限 80 MiB。未变化的大文件可校验后跳过 |
| 二进制或非 UTF-8 文件 | 显示摘要，不提供普通文本编辑体验 |
| 符号链接 | 只读链接文本，不跟随目标文件 |
| 子模块 | 需要单独打开为仓库审阅 |
| Git LFS、换行规范化或其他过滤器 | 按原始磁盘字节比较，不执行 clean、textconv、external diff 或换行转换，结果可能与 Git 自身展示不同 |
| 评论容量 | 普通评论区和已删除恢复区分别最多 2,000 条，跨 CR 计数；已解决评论也计入，归档不释放容量 |
| 代码选区 | 最多 200 行；通过片段和上下文定位，不做 AST 跟踪或自动改名迁移 |

读取失败、合并冲突、损坏快照或超出限制不会被视为“没有变化”，也不会产生成功的已审结果。先处理提示中的原因，再刷新并核对。

## 遇到问题时

| 看到的情况 | 可以先做什么 |
| --- | --- |
| 没有出现 ReviewSlate，或找不到仓库 | 核对扩展版本和兼容内核；确认工作区受信任、是文件系统目录、仓库至少有一个提交且当前宿主能运行 Git。Remote SSH 还需核对远端安装 |
| Git 图形没有新建审阅菜单 | 复制提交 SHA，通过命令面板执行“ReviewSlate：从提交 SHA 新建审阅…” |
| 文件显示“未保存”，不能勾选或给工作区侧代码添加选区评论 | 先保存编辑，再从当前 CR 打开文件、检查最新 Diff 并操作 |
| 点击后提示 CR、分支或内容已变化 | 刷新，核对当前仓库、分支、CR 和内容后重试。切换 CR 后不要从旧 Diff 标签为当前 CR 写代码评论 |
| 评论保存报错，但似乎已经出现 | 保留草稿，先刷新核对。评论可能已保存，只是交接清单生成失败；不要立即另建一条相同评论 |
| 评论无法定位或文件已经改名 | 查看保存的原片段与上下文，人工确认当前位置；扩展不会按旧行号猜测或自动迁移评论 |
| 数据文件损坏或主文件缺失 | 保留主文件、`.bak` 与现状副本。扩展不会静默载入空进度或自动采用备份；确认格式、归属和快照完整后再人工恢复 |
| 提示另一写入者或残留锁 | 先确认并停止其他写入者；只有确认没有相关进程仍在写入时，才能按数据协议处理残留 `write.lock` |
| 永久删除未完成 | 保留当前资料，从对应记录再次执行永久删除；不要手工清除删除标识后继续使用 |

仍无法解决时，在 [Issue](https://github.com/To-Re/review-slate/issues) 提供扩展版本、编辑器与系统版本、是否使用 Remote SSH，以及可重复的操作和预期结果。优先使用合成仓库复现，附脱敏后的错误文本；安全问题按 [SECURITY.md](../../SECURITY.md) 报告。
