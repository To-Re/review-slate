## 使用前准备

需要本机可运行的系统 Git、至少有一个提交的本地 Git 仓库，以及能够加载该插件的 Codex 桌面宿主。当前包以 Apple Silicon Mac、macOS 13+ 为目标，最低系统版本兼容性尚待实测；其他系统、架构和远程工作区未列入支持范围。

完整候选包捆绑 Node.js 和系统文件夹选择组件，使用时无需另装运行时、部署服务或为 ReviewSlate 配置模型账号。文件夹选择窗口只在点击选择时出现，完成或取消后退出。

开发试用需先构建并安装候选包：构建步骤见[贡献指南](../../CONTRIBUTING.md#codex-候选版)，安装配置和开发环境的验证证据见[接入记录](../客户端/Codex接入.md)。源码更新和打包不会自动安装插件；使用前请确认本机实际安装的版本。整体状态见[项目现状](../项目现状.md)。

更新安装后，先等待底部显示“导航与草稿已在本地保留”，再完全退出并重开 Codex，确保 ReviewSlate 加载 0.1.2。只关闭面板可能仍沿用旧版进程。升级不改变数据目录或格式，已有进度、评论与已保存草稿无需迁移。

以下操作从已打开的 ReviewSlate 工作区开始。

## 选择项目与界面语言

顶部“当前项目”显示正在审阅的仓库，点击“切换”打开项目选择：

- **最近项目：** 点击项目即可打开。
- **选择文件夹…：** 在系统文件夹窗口中找到 Git 项目并确认选择，校验成功后直接打开。可以选择仓库内的子目录，应用会找到实际仓库根，无需选择隐藏的 `.git`。
- **手动输入路径：** 需要时再展开，在“仓库目录”填写本地绝对路径，例如 `/path/to/repository`，点击“打开项目”。这是系统选择不可用时的备用方式。

取消系统选择会回到项目选择弹窗，不改变当前项目、CR、草稿或最近记录。选择的文件夹不是 Git 仓库或打开失败时，原项目保持不变，按提示重新选择；不会自动创建 Git 仓库。最近项目每次打开仍会检查路径与访问权限。切换项目不会切换 Git 分支，也不会导入其他应用的审阅数据。首次新建审阅时才确认启用本仓库的保存位置。

点击顶部“设置”，在“界面语言”中选择：

| 选项 | 显示方式 |
| --- | --- |
| 跟随宿主 / Follow host | 宿主语言为中文时使用简体中文；其他语言或没有语言信息时使用 English |
| 简体中文 | 固定使用简体中文 |
| English | 固定使用英文 |

选择语言后会自动保存；看到“语言偏好已保存”后，重开仍会保留，设置适用于所有仓库。保存失败时保持原语言，按提示重试。语言设置不会翻译代码、路径、分支、评论或 Agent 回复，也不会替你提交草稿。设置内的“新建审阅的默认基点”只影响以后新建时的默认选择，不改变当前 CR。

## 新建或接续一轮审阅

点击“新建审阅”，选择本轮比较的起点。审阅记录简称 CR，用来保存固定基点、已审进度和评论。

| 基点方式 | 实际比较起点 |
| --- | --- |
| 分支共同祖先 | 所选本地或远端分支与当前 `HEAD` 的共同祖先 |
| 指定提交 SHA | 输入并校验的本地提交本身 |

确认后固定完整 SHA，之后分支推进不会悄悄改变本轮起点。身份条持续显示当前分支、CR 和固定基点，可以查看或复制完整 SHA。ReviewSlate 不会自动 fetch；需要更新远端引用时，在 Git 中自行完成。

首次点击“启用并新建审阅”会在仓库中建立 `.reviewslate/codex/`，保存本应用的审阅资料，并按需向根 `.gitignore` 追加 `/.reviewslate/codex/`。已有内容保留，不修改 Git 索引。具体资料范围见[Codex 数据与故障处理](Codex数据与故障处理.md)。

同一仓库、分支与固定基点已有未归档 CR 时，会接续原记录。需要查看其他轮次时，从“审阅记录”打开；其他分支的活动记录需先自行切到对应分支，再返回刷新。

## 阅读 Diff，保存已审进度

左侧文件树包含整轮变化与仍有评论的对象。选择文件查看完整 Diff：左侧是固定基点，右侧是磁盘上**已经保存的工作区**；暂存区没有单独的一侧。选择目录可查看该范围的进度和意见。0.1.2 中，目录展开箭头与已审复选框更容易点击。

**当前版本提供只读对比。** 需要修改代码时，在自己的编辑器或经授权的 Agent 中修改并保存，再使用“变更文件”标题旁的刷新。ReviewSlate 不能读取外部编辑器尚未保存的缓冲，因此已审标记只代表你检查过的磁盘内容。

0.1.2 打开单文件 Diff 时只读取目标内容，不扫描全仓，也不等待后台刷新完成；仓库、分支和 CR 仍会校验。保存草稿与切换文件不会重建整棵目录树。后台刷新会根据耗时调整间隔；完整刷新和标记已审仍可能随仓库规模耗时，合成仓库的[性能验证](../测试/验证记录.md#2026-11-03-大型-idl-仓库性能验证)不代表真实 Codex 面板速度。

检查后，勾选文件或目录，或使用文件头的“标记已审”。目录操作针对其中的变化文件；读取失败不会产生成功的已审结果。仅有评论而没有变化的对象不计入变化文件总数。

如果提示文件内容已变化，先刷新并复核当前内容，再保存评论或标记已审。单文件 Diff 显示最新内容，不表示整轮变化列表已经刷新。

内容未变时，stage 或 commit 不会清空已审标记。内容、文件类型或执行权限变化后，需要复审。选择“上次审阅后的变化”可比较上次标记已审的工作区快照与当前内容；检查完后重新标记已审，后续增量以这次内容为准。

## 记录意见与保留草稿

| 意见范围 | 操作 |
| --- | --- |
| 文件 | 选中文件，在意见栏输入并“保存评论” |
| 目录及子项 | 选中目录，保存目录意见 |
| 一段代码 | 在完整 Diff 的任一侧选择 1–200 行，点击“为选区写意见”，确认原片段后保存 |

代码选区保存原片段和上下文。内容仍可唯一匹配时可以跟随行号移动；相关代码改变或位置不确定时，查看原片段并人工确认。文件改名不会自动搬迁评论。不支持文本选区的内容可以使用文件意见。

评论支持编辑、解决、重新打开、删除与恢复。删除单条评论后，可在对应对象的“已删除”卡片恢复。待处理入口集中展示本轮未解决意见，包括已经收到匹配 Agent 回复、仍待人工复核的意见。**解决评论和标记文件已审分别操作。**

新评论草稿和原评论的编辑草稿会按 CR 保留，选区草稿包含侧别、原片段与上下文。底部“导航与草稿已在本地保留”表示输入已保存为草稿，仍需点击“保存评论”才成为正式评论。出现“尚未保留”“正在本地保留”或“本地保留失败”时，保持页面打开，等到保存确认；恢复后不会自动提交评论。

0.1.2 保存草稿不扫描源码，也不等待后台刷新；文件内容变化本身不会阻止保留输入。保存仍会核对分支、CR 和草稿版本，失败时以页面提示为准。

切换对象、CR 或仓库前会尝试保留输入；失败时停在原处。若另一窗口改过原评论，编辑草稿会保留，但需核对当前版本，不能用旧输入直接覆盖。关闭前尚未确认保留的最后输入不保证恢复。

## 可选：交给 Agent，再由自己复核

1. 点击“交给 Agent”，核对仓库、分支、CR、完整基点和拟处理评论。已有匹配回复的意见保留为待复核上下文，默认不重复交给 Agent 处理。
2. 点击“生成并复制固定说明”，检查其中的资料范围，再自行发送给能够访问该项目的 Codex 会话。复制受限时，从显示的文本框手动复制。
3. Agent 按固定说明核对身份与评论版本，在你的授权范围内处理，并写入对应回执。说明绑定生成时的批次，切换 CR 不会把它改成另一轮任务；评论已改变时，应停止该条并重新确认。
4. 回到工作区刷新。匹配当前评论版本的回执显示“Agent 已回复 · 待复核”；检查代码、回复和验证结果，复审受影响文件，再决定是否解决评论。

复制不会发送消息、启动 Agent、调用模型或解决评论。交接资料可能含绝对路径、代码和评论，发送前确认接收方及访问范围。旧版回复仍可查看，但不表示当前版本的意见已经处理。

## 重开、归档与删除

重开同一仓库时接续当前分支的活动 CR。已确认保存的评论、已审记录、导航与草稿可恢复；文件内容改变后，只按能够确认的片段定位，不保证沿用旧行号。当前没有多份历史草稿的选择或合并界面。

结束前检查未审、需复审、读取错误和未解决意见，再从“审阅记录”归档。归档保留资料，可只读查看评论、回执和已有已审快照；它没有保存归档时所有未审文件，不能当作当时的完整工作区。归档查看期间的导航仅留在本次页面内。恢复后才重新比较当前磁盘；若同分支和基点已有新 CR，先处理该记录冲突。

永久删除需核对目标并输入 `DELETE`，会清理该轮进度、快照、评论、回执、草稿和导航，不能在应用内撤销。它不修改工作区代码或 Git 元数据，也不是磁盘安全擦除。删除未完成时按页面提示继续清理，不手改删除标识。故障恢复见[数据与故障处理](Codex数据与故障处理.md#遇到问题时)。
