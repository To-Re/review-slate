## 验证约定与入口

开发环境与依赖安装见[贡献指南](../../CONTRIBUTING.md#本地开发)。代码或打包变化交付前运行 `npm test` 与 `npm run package`；开发时可先编译，再定向运行相关测试：

```sh
npm run compile
node --test test/comments.test.cjs test/reviews.test.cjs
```

测试只使用临时合成仓库与虚构样例，不隐式启动编辑器、修改安装或操作真实审阅数据。根据变更选择正常路径、错误恢复、归属隔离和回归场景；纯文档变化核对事实、入口与链接，不为数量重复全量测试。

| 证据类型 | 可以支持的结论 | 不能据此推定 |
| --- | --- | --- |
| 静态核查 | 某版本代码、配置、文档或产物的内容 | 运行成功、界面可用或已发布 |
| 单元与模拟测试 | 受控输入下的规则、UI 脚本和模拟桥接结果 | 实际 DOM 布局、真实宿主权限与生命周期 |
| 集成测试 | 真实 Git、文件系统或 stdio 进程在已测场景中的结果 | UI 已展示保存结果、其他宿主同样支持 |
| 真实宿主与界面观察 | 指定宿主、版本和操作下的可见状态及最终落盘结果 | 未测流程、其他平台或完整产品验收 |

每次验证记录日期、提交及未提交差异、产物版本、环境、命令或操作、预期与实际、证据和缺口。状态使用“通过 / 失败 / 未执行 / 阻塞 / 不适用”，不适用说明理由；失败还应给出前置条件、复现步骤、影响与修复负责人。历史结果只证明历史版本，其他角色提供的观察要注明来源。敏感日志与大产物留在受控存储，公开文档只留脱敏索引。

界面变化按受影响流程补验真实宿主，包括主题、窄屏、长文本、键盘操作和异常状态。QA 交付同一版本的证据与缺口后，由设计和产品分别验收实际成品；测试通过不替代这两项结论或发布授权。

### 正式实现的定向入口

独立 QA 用例在 [qa-integration.test.cjs](../../test/codex/qa-integration.test.cjs)，直接调用正式 `CodexController`，使用临时真实 Git 仓库和隔离应用数据目录，评论请求复用正式 UI 的 payload builder。它覆盖完整树与 Diff、内容已审及三类评论、同路径跨仓库/CR、分支与内容陈旧写入、视图 CAS 与重试、重新构造 controller 后恢复、语言偏好、固定交接与回执、归档删除、VSIX 数据隔离及存储拒绝；在操作回执替换处注入单次 EIO，核对实际已写入与返回的结果分类。组合 Unicode 草稿超过 16 MiB 时，另核对拒绝写入、原副本字节保持、重开恢复及后续正常保存。

[qa-stdio.test.cjs](../../test/codex/qa-stdio.test.cjs) 启动真实 MCP stdio 子进程，验证协议声明、工具结果的组件数据边界、EOF 退出、新进程恢复、客户端丢弃回执后的查证，以及两个进程竞争同一评论版本。可模拟丢弃成功回执，不能因此声称做过断电或物理磁盘故障测试。以下命令可重复执行；本轮 11 项集成结果及随后默认基点的定向复验见[正式实现记录](验证记录.md#2026-11-03-codex-正式实现的独立验证)。

```sh
npm run compile
node --test test/codex/qa-integration.test.cjs test/codex/qa-stdio.test.cjs
```

本轮由主负责人执行全量 `npm test`、VSIX 与 Codex 打包，QA 运行所属定向场景；UI 负责人维护 `ui*.test.cjs`，独立 QA 测试采用 `qa-*.test.cjs` 避免共同写入。多进程竞争与工具重启使用真实 stdio 子进程，不能由两个 controller 实例冒充跨进程结果。代码编辑能力须单独通过 E1；产品已将 0.1.x 定位为只读人工审阅候选，当前 `editCode: false` 与本轮范围一致；直接编辑与代码恢复仍延后 E1，不据此宣称整个 AC-06 通过。

为避免并行构建改变被测输入，QA 可将已编译的 `dist/` 复制到独立产物目录，并设置 `REVIEW_SLATE_QA_DIST` 为该目录执行上述测试；默认仍使用仓库 `dist/`。记录复制输入的文件指纹和源码范围，不把该隔离副本当安装包或发布产物。

### 大型 IDL 仓库与文件切换性能

[qa-performance.test.cjs](../../test/codex/qa-performance.test.cjs) 使用临时合成仓库，验证单文件 Diff 与草稿保存不触发全仓扫描、目标内容实时读取、后台刷新期间保存后打开 Diff、分支 / CR 归属、并发草稿 CAS 与重试，以及批量对象对应、提交后已审保持和内容变化复审。扫描计数和可控挂起用于捕获重复扫描、队列阻塞；测试中的等待上限是防止挂起，不是产品延迟承诺。

```sh
npm run compile
node --test test/codex/qa-performance.test.cjs
```

规模基准与功能回归分开记录。合成 IDL 文件路径、内容及 Git 身份必须全部虚构；不在实际业务仓库制造状态。分别测首次基点、已有审阅冷开、稳定刷新、单文件 Diff、标记、草稿保存，以及先保存草稿再 Diff 和刷新进行中的 Diff。记录同一 Node / Git / 架构、样本规模、耗时、Git 进程数、工作区文件检查 / 读取量和返回字节，不把控制器结果当成真实面板点击耗时。前后实测与本地重跑方式见[性能验证记录](验证记录.md#2026-11-03-大型-idl-仓库性能验证)。

### 最终候选的界面检查入口

0.1.1 UI 曾由 QA 在获准的独立 `ReviewSlate Client Test Host` 中实际操作；历史流程、包摘要、截图/AX、磁盘恢复结果及未覆盖范围见[对应版本检查](验证记录.md#2026-11-03-最终-ui-候选的独立-gui-功能检查)。0.1.2 最终包的树热区与键盘焦点由设计独立操作同类 AppKit / WKWebView 测试宿主复验，结果见[最终候选记录](验证记录.md#2026-11-03-codex-012-最终候选收尾)。这些宿主均加载实际候选 UI 与 stdio 服务，仍不是 Codex。主负责人负责该测试应用的构建与授权，常规自动化不得隐式启动它或操作日常 Codex。

新增或调整仓库/设置界面时，优先复验最近项目、失败路径保留、跨仓库独立草稿、语言即时保存与重开、默认提交回填及不改变当前 CR；跨过后台刷新周期检查输入与焦点，再核对评论保存及应用重开。系统文件夹选择另覆盖原生浏览、取消、重复点击、系统“前往文件夹”子窗口、非 Git 目录原弹窗重选，以及相邻同名但仅末尾空格不同的两个真实合成仓库。非 Git 目录须位于测试仓库及项目仓库之外，否则 Git 会正确识别祖先仓库，无法构造该错误条件。helper 正常结束后通过客户端结果与应用清单核对，不再次用会自动启动应用的 `getApp` 检查退出。候选目录拒绝后须关闭弹窗，实际验证原项目 Diff、已审和评论保存仍可用，再核对原稿与重开；同时保留切换前保存失败、未知结果和部分写入的全局守卫，不能以候选错误隔离清除已有故障。只在实际触发对应失败条件后，才记录复制回退、未知操作恢复或权限拒绝通过。同一候选交给设计检查宽窄、主题与键盘，交给产品验收连续任务。

### 保存与恢复的观察点

这些场景规定验收应观察的结果；部分 controller、真实文件系统和 stdio 场景已经执行，逐项结果见[正式实现记录](验证记录.md#2026-11-03-codex-正式实现的独立验证)，**完整真实 Codex 验收仍未执行**。每个场景同时观察页面、请求归属与版本、工具返回及磁盘最终状态；不能把其中一层成功推定为其他层成功。产品规则见[保存、草稿与接续](../产品/业务规则.md#6-保存草稿与应用内接续)，字段与存储位置由[客户端数据协议](../客户端/数据协议.md)维护。

| 对象与关联 AC | 正常路径 | 失败或边界及判定依据 |
| --- | --- | --- |
| CR、已审与快照；AC-03、05、11 | 保存确认后结束工具进程并重新启动，再重开界面；核对 CR、基点及内容身份 | stage / commit 内容不变；单文件变化只使该文件复审；保存前分支或 CR 变化则拒绝，原记录不变 |
| 新评论及选区草稿；AC-07、08、12 | 分别保存目录、文件和两侧选区草稿，切对象与重开；核对正文、类型、路径、侧别、原片段和上下文 | 保留失败不能显示“已在本地保留”；选区内容变化或路径消失仍保留原文，不自动变为文件评论；基点侧不能用工作区内容判失配 |
| 原评论编辑草稿；AC-07、10、12 | 先留新评论草稿，再编辑原评论、离开及重开；取消编辑后新草稿仍在 | 原评论 revision、删除或解决状态已变时保留输入并拒绝覆盖；成功修改保持 ID、更新版本，旧回执不再待复核 |
| 代码缓冲及恢复副本；AC-05、06、12 | 启用编辑时分别观察缓冲、已确认恢复副本及已保存工作区；重开只恢复缓冲 | 有未保存代码时文件及祖先不能标已审；外部改动、类型/权限或路径变化拒绝覆盖；失败保留输入；恢复副本不能算代码已保存 |
| 导航；AC-12 | 保存对象、展开、视图和定位上下文，切 CR、仓库、分支切回及关闭重开 | 原对象消失时保留路径和意见入口；位置失配不伪造准确跳转；空 CR 不显示上一轮内容；迟到响应不改变当前对象 |
| 并发与不确定写入；AC-11、12、15 | 同请求重试仍只有一次业务写入；超时后先读回再确认结果 | 两页面以同版本更新，至少一个明确冲突；旧页不得写新 CR；在写入前、中间、替换完成但回执丢失处注入故障，核对旧值、新值或明确恢复状态，不能自动清空 |
| 归档及永久删除；AC-13 | 归档后数据与恢复副本保留且禁写；只读资料不冒充归档时完整工作区；恢复冲突保留双方；永久删除明确清理范围 | 逐阶段中断并重试；仅目标 CR 的数据、草稿及导航被删除，其他 CR、代码、Git 元数据不变；旧页和旧交接不能复活记录 |
| 应用隔离及存储保护；AC-14、15 | 同一合成仓库分别用 VSIX 与 Codex 写入并重开，前后对另一端数据做文件指纹比较 | 只换扩展存储根并不足以隔离评论；覆盖符号链接、既有目录占用、损坏/未知版本、权限错误与忽略规则追加，失败不能创建空进度冒充恢复 |

保存故障至少分别检查“未写入”“已落盘但回执丢失”“结果仍无法确认”，测试代码不能仅模拟一个统一错误。异常退出只承诺恢复已确认保留的副本；未确认输入的损失边界必须在界面中可辨。代码文件写入另核对可执行权限与原始字节，不沿用生成数据文件的 `0600` 写入假设。

### 设计阶段的辅助核查

以下文件位于被忽略的本地产物目录，**普通 checkout 不包含**；仅在持有[验证记录](验证记录.md)对应版本时运行。不得为执行它们安装或启动真实 Codex。设计原型使用合成数据和本地存储，没有 Git、stdio 或产品接口。

```sh
node --check artifacts/codex-design/app.js
node --test artifacts/codex-design-qa/prototype-semantics.test.cjs
node --test artifacts/codex-client-design/core-seams.test.cjs
```

第一组模拟 DOM、存储失败与事件，检查原型的保存文案、归档/访问失败禁写、双侧选区、代码缓冲、评论版本和重建脚本上下文后的接续。它不执行浏览器排版，不证明键盘、可访问性、真实磁盘持久化或宿主权限。第二组在临时合成仓库中检查核心可加载性、评论目录仍固定在旧数据范围，以及现有数据写入函数的权限行为；它用于确定必须改造的边界，不表示 Codex 隔离存储或工作区编辑已经实现。

原型视觉与交互由自有 Preview 应用另行观察，必须注明它是 WKWebView 预览及所加载的文件指纹。真实 Codex 未获可执行入口或无法操作时保留未执行/阻塞，不能以改名、模拟宿主或独立应用替代。

### 后续验收的执行门槛

开发顺序沿用[产品阶段出口](../产品/README.md#开发顺序与阶段出口)。进入每一阶段前，只要求与其风险相应的证据，不把全部产品验收提前，也不把数据保护推迟到最后：

1. **宿主接入。** 绑定目标 Codex 版本与可复现安装配置，取得入口显示、页面点击、工具调用、实际落盘、关闭重开和子进程退出证据；用合成标记检查 app-only 工具及组件专用数据不意外进入模型可见正文，同时核对无 HTTP 监听。此门槛未过，可继续隔离核心和原型开发，不能宣布宿主接入完成。
2. **首个正式读写。** 客户端先把独立存储根、请求归属、版本冲突、幂等重试、失败不覆盖及恢复格式落实为代码契约；QA 从第一条 CR 和评论写入开始执行上表，不直接搬用合成探针 revision。
3. **直接编辑启用。** 先验证目标文件权限、原始字节、外部改动、未保存保护、恢复副本及写入结果不确定，再开放实际写入。若门槛未过，交回产品记录 AC-06 的适用方式；编辑优先设计不变成用户必选，也不能据暂时只读宣称完整任务通过。
4. **候选包完整任务。** 同一可安装产物完成 AC-01 至 AC-17 的适用场景与连续任务，补主题、窄屏、长文本、键盘及实际退出；随后交设计与产品验收该版本。VSIX 兼容和双应用隔离单独取证，不能借历史结果补记通过。

## 更新与交接

行为、接口、存储格式或支持环境变化时，QA 更新受影响场景并验证实际候选版本。缺陷修复只复测其影响范围与必要回归；源码未变的纯文档整理不重复已有全量测试。

[验证记录](验证记录.md)保留目前仍有用的发布证据和未关闭缺口。新结论写明替代的版本与范围，不用新日期刷新旧通过；受影响证据失效时立即改为待验证。临时脚本与本地产物若不随 checkout 提供，必须明示，并给出复现方法或文件哈希。

交接给项目负责人时，提供已测版本、环境、方法、结果、缺陷及可复查证据；未完成项附影响、下一责任和解锁步骤。涉及界面与流程的候选版本还需交设计、产品分别验收，任何单项通过都不等于发布许可。
