## 当前扩展能做什么

| 能力 | 实际行为与限制 | 权威入口 |
| --- | --- | --- |
| 固定基点审阅 | 选择主分支的共同祖先或指定提交，固定完整 SHA，对比磁盘上已保存的工作区 | [产品](产品/README.md)、[使用指南](用户文档/使用指南.md) |
| 多轮 CR | 每个仓库按分支与固定基点保存进度；同一未归档组合复用；切回分支接续原记录 | [产品](产品/README.md)、[本地审阅引擎](客户端/本地审阅引擎.md) |
| 已审与复审 | 内容未变时 stage / commit 不清空进度；内容变化后需复审；目录汇总部分已审 | [产品](产品/README.md)、[设计](设计/README.md) |
| Diff 与编辑 | 使用编辑器原生 Diff，完整对比右侧符合条件的普通 UTF-8 文件可编辑保存 | [客户端](客户端/README.md) |
| 评论与人工复核 | 文件、目录、选区评论；可操作待处理列表；定位不确定时保留原片段；Agent 回执由人复核 | [使用指南](用户文档/使用指南.md)、[数据协议](客户端/数据协议.md) |
| 本地持久化 | CR 与快照在扩展存储，评论与回执在 `.code-review/`；完整备份需要两处数据 | [数据协议](客户端/数据协议.md) |

实现存在与实机通过分别判断。1.0.1 在 macOS / Trae CN 3.4.11（内核 1.107.1）验证了安装、重载及所列入口；VS Code、Trae、Remote SSH 尚无本版本完整实机验收。112 项合成仓库自动测试及 Ubuntu/macOS CI 属于该发布基线的历史证据，详见[验证记录](测试/验证记录.md)。

## 系统与数据边界

当前扩展在编辑器宿主中运行，使用 Node.js 内置模块和只读 Git。没有服务部署、HTTP 监听、遥测或插件自建上传通道。用户在 Diff 中保存会修改工作区；评论初始化会补充根 `.gitignore`。安全边界见[安全](安全/README.md)。

数据以普通本地文件保存，快照和评论可能包含代码与绝对路径。`.code-review/` 不包含完整进度；不同宿主扩展存储各自独立，没有自动迁移或同步。Codex 首版按应用独立保存数据，跨应用互通已明确排除在本阶段之外。

Codex 在宿主内提供 MCP App 审阅工作区，由宿主管理 stdio 子进程；仓库内独立 `.reviewslate/codex/` 保存本应用资料。界面、入口和安装包独立，共用 Git 对比、审阅判定与评论规则。共用部分变化仍需验证 VSIX 回归。CodeMirror 当前仅提供只读 Diff，直接编辑尚未实现；安装、宿主数据隔离与界面验收门槛见客户端文档。

## 当前限制与未实现范围

- Codex 的真实面板显示、界面到工具的保存与重开恢复尚未完成验收。独立测试应用通过不能替代真实 Codex 验收。
- Codex 完整人工审阅、可移植安装包及 DeepSeek Harness 插件尚未交付；Harness 按用户决定延后。
- 当前扩展的数据恢复不等于已验证关闭重开后恢复全部文件选择、目录展开和 Diff 定位；这项连续导航是 Codex 的明确目标。
- 代码选区定位不做 AST 或自动改名跟踪；二进制、大文件、符号链接、Git 过滤器和未保存内容有明确边界，见[数据协议](客户端/数据协议.md)。
