# 协作规范

负责人：主负责人；状态：现行；最后核查：2026-11-03。适用范围：ReviewSlate 的产品、设计、研发、验证与文档协作。依据：已采用的专业角色维护协议与本项目最新要求；本文件提供仓库内可独立使用的规则，不依赖贡献者安装个人配置。

## 指挥与专业责任

主负责人明确用户目标、已有决定、权限、依赖、共享文件负责人及完成条件，协调跨领域问题并整合交付。专业角色按自身职责查证事实、提出方案、完成实施或验证，直接维护[索引](README.md)所列的角色目录；主负责人不以逐段提纲代替专业判断。

每个角色方向一个目录。产品、设计、客户端、测试、代码评审、安全、用户文档和编辑各有权威入口；主负责人只维护总索引、项目现状、项目状态与本协作规则。写作可以协助表达，领域事实仍由责任角色确认；编辑在自己的目录记录独立评稿结论，不复制第二份当前正文。

同一文件同阶段只有一个写入者。角色发现需要改共享契约、其他目录或公共配置时，先把问题交回协调，不能覆盖他人工作。角色名称不扩大系统权限、发布范围或用户授权。

新子角色独立接收任务材料，不复制完整父会话，不使用私有持久记忆。主负责人是第 0 层，最多派生到第 2 层；任务包给出实际层级、剩余额度、直接父角色与全树并发份额。第 2 层不得再委派，额度不足时汇总问题，不能通过转派重置层级。按需启动必要角色，不为齐人数重复审查。

## 项目事实如何保存

- [项目现状](项目现状.md)描述当前完整能力、限制、实现与发布边界；[项目状态](项目状态.md)记录在途目标、依赖、遗留和下一步。
- 领域正文说明当前规则与方案。代码类型、读取校验等是字段级契约来源，文档链接它们，不手抄第二份可写 schema。
- 验证记录绑定提交或工作区范围、日期、环境、方法、结果与证据。结果使用“通过、失败、未执行、阻塞、不适用”，不适用说明理由。
- 规范写负责人、状态、适用范围、核查日期和来源。日期只在实际核查或实质修改时更新。
- 需求、设计、实现、实际验证和公开发布分别表述；不能用测试文件、原型、历史通过或角色共识证明当前版本已验收。

行为与范围变化时，同次更新领域正文及受影响的现状、用户说明和测试入口。维护当前正文，清理已替代文件和失效引用；不再保留旧文档副本、跳转页或归档目录。仍适用的决策依据、有效证据和未解决问题纳入现行文档，代码历史由 Git 保留。

## 实现与验收

需求不清由产品澄清，体验不清由设计处理；客户端研发统一负责插件本地逻辑、数据和宿主适配，按实际需要拆分模块任务。QA 按风险制定并执行验证，不把实现代码直接翻译成断言。代码或打包变化交付前执行 `npm test` 和 `npm run package`；纯文档变化核查事实、引用与披露范围，不机械重跑无变化的功能。

实质性实现变更由独立代码审核者检查；权限、外部输入、敏感数据或高权限工具边界变化加入安全审核。审核者默认只读，仅在明确分配时维护报告。不能由作者自审后宣称独立通过。

产品或界面变化在 QA 后，由适用的产品与设计角色验收同一实际版本。设计需要实际页面或可核查的成品证据，产品核对完整任务和恢复路径。模拟宿主、接口返回、磁盘状态、真实界面是不同证据层级；截图不证明交互，接口成功不证明显示正确。

缺陷交责任研发修正，QA 复测受影响范围，提出问题的领域复验。无新变化不重复全套流程。未完成验收或阻断问题仍在时保留未完成状态；遗留项写清影响、负责人和可执行下一步。

## 运行、隐私与发布

正式运行约束沿用 [AGENTS.md](../AGENTS.md)、[客户端](客户端/README.md)及[安全](安全/README.md)。只读 Git、现有数据兼容、失败不伪造成功、跨 CR 写入归属、测试用合成仓库等要求适用于所有适配器。

凭证、个人绝对路径、公司内部资料、真实审阅内容、原始日志和截图不进入公开仓库。大产物与本机试验放忽略目录，公开记录只保留脱敏的版本、范围、指纹与结论。测试不得隐式安装或启动编辑器。

推送、发布或扩大发布范围前，独立安全审核绑定真正要披露的提交、历史增量、包、媒体、文案和目标；审核后变动补查。已有有效授权继续执行，审核不创造新授权。开发完成、验证通过、已安装和已发布分别确认；没有远端证据不能写成发布成功。
